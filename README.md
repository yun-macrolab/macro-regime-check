# macro-regime-check

미국 공개 통계(FRED) 23개 시리즈를 받아 코드로 공개된 **규칙 13개**가 충족됐는지 판정하고, 미국 영업일 다음 날 아침(KST 화~토 07:17)마다 자동으로 갱신하는 점검 페이지입니다.

**[점검 페이지 보기](https://yun-macrolab.github.io/macro-regime-check/)** · 투자 판단이나 권유가 아니라, 공개된 규칙을 공개 통계에 적용한 출력입니다.

| 하는 것 | FRED 원자료 수신(API 키 없이 공개 CSV) → 전년비·3개월 변화·60영업일 상관 등 계산 → 규칙별 충족 / 미충족 / 판정 불가 → 공개본·그래프 자료·상태 기록 → 페이지 배포 |
| 싣지 않는 것 | 주간 평가 시트의 듀레이션·커브 판정과 사람이 고친 점수, 그리고 이용 조건상 재배포할 수 없는 값 — ICE BofA 회사채 OAS(등급별·장기·HY·IG)의 값과 그로 되살릴 수 있는 등급 간 차이·변화, S&P 500의 값·수익률·13주 변화 %, Nasdaq 지수의 값·수익률·고점·낙폭 시계열. 이런 자료는 규칙 충족 여부·ON/OFF·방향(상승·하락·보합)과, 원값을 되살릴 수 없는 상관·회귀 계수만 계산값으로 싣습니다. 2026-10-30 이용 조건을 검토한 뒤 운영자가 위험을 알고 받아들여 회색 지대 둘을 싣습니다 — Moody's Baa−10년의 수준·12개월 저점 대비·1990년 이후 분위, 나스닥100·AI 지수의 252영업일 고점 대비 정수 낙폭 %([아래](#공개-원칙-2026-10-30-바꿈)) |

| 해석과 측정 기록 | 2026-10-30부터 운영자의 비공개 월간 점검 알림에만 있던 줄 — 시나리오 이름표(A~D)와 해석 구절, 국면 참고값, 손으로 보는 항목, 참고 카드의 측정 기록(신용 긴축 단계와 가설·경로 숫자, 기간 프리미엄 주간 점수, 유가 방향 상태별 평균, AI 고유 몫 등) — 도 '참고 — 예측 아님'·'측정 기록' 표시와 함께 싣습니다. 규칙의 충족 여부는 여전히 규칙 문장만으로 정해집니다 |
| 참고로 싣는 것 | 한국 국고채 금리(3·5·10·30년) — **공개 통계가 아니라** 증권사 리서치팀 텔레그램 공개 채널 글에서 옮긴 숫자이고, 규칙 판정에는 쓰지 않습니다([아래](#참고-한국-국고채-금리)) · 미 국채 수급 두 지표(딜러 순포지션 · 해외 공적 수탁) — 공개 통계지만 규칙이 아니라 기간 프리미엄 카드의 참고 칸입니다([아래](#참고-미-국채-수급-두-지표)) · 유가·에너지(원유·소매 휘발유·경유·정제 마진·CPI 에너지·I4 꼬리표·기대인플레이션·시추·가동률, 한국은 Brent·두바이 × 원/달러) — 물가 묶음의 참고 카드와 한국 시장 화면의 줄입니다([아래](#참고-유가에너지)) · 2026-10-30 더한 참고 카드 다섯 — 레짐 점검 참고([아래](#참고-레짐-점검과-해석-줄)), 기간 프리미엄 모형 대조(Kim-Wright · 뉴욕 연은 ACM, [아래](#참고-기간-프리미엄-모형-대조)), 지준·재정([아래](#참고-지준재정)), 신용 긴축과 하이퍼스케일러 조달(SEC 공시, [아래](#참고-신용-긴축과-하이퍼스케일러-조달)), 단일종목 CDS(DTCC 공개 거래 보고, [아래](#참고-단일종목-cds)) · 연준 재무상태표(2026-11-03) — H.4.1 주간 지준·지준/GDP·4주/13주 지준 변화의 나눔·단기자금 5영업일과 지준 관리 매입(RMP) 칸(뉴욕 연은 월 일정 공지의 계획 금액 — 머리 한 줄·묶음 표·RMP 시작 뒤 지준 나눔·규칙 하한의 달러 크기·운영 결과 대조의 차 한 줄)·연준 대차대조표 정책 사실(1차 출처, 고정 글), 유동성 화면의 참고 카드([아래](#참고-연준-재무상태표)) · 연준 인물(2026-11-01) — FOMC 참가자 19명의 출신·걸어온 길·말하는 방식·평판·표결과 새 발언을 견줄 기준선, 사람이 고치는 초안의 별도 페이지와, 그 페이지의 새 발언 자동 분류(2026-11-04 — 언어 모델(AI)이 기사를 읽고 운영자가 정리한 기준선에 견준 결과, 사람 확인 없이 매일)([아래](#참고-연준-인물)). 어느 것도 규칙 수에 들지 않습니다 |

23개 중 원/달러·M2 유통속도·IG 스프레드 3개는 규칙에 쓰지 않습니다. 원/달러·M2 유통속도는 '레짐 점검 참고'의 그 밖의 관측값으로 값을 싣고, IG 스프레드(ICE)는 전환 경계 t2의 ON/OFF와 자료 상태만 싣습니다.

## 공개 원칙 (2026-10-30 바꿈)

전에는 '제 시장 견해와 해석 문구는 싣지 않는다'가 원칙이었습니다. 2026-10-30 제 결정으로 **비공개 알림에만 있던 줄을 모두 공개하기로** 하고, 이용 조건이 막는 값만 남겼습니다.

- **새로 싣는 것** — 규칙 카드의 시나리오 이름표와 해석 줄, '레짐 점검 참고'(핵심 신호 n/m · 국면 후보 · ρ60 경보 · 근원 CPI<3% · 전환 경계 · 손으로 보는 항목 · 그 밖의 관측값), 수급 참고의 ⚠ 줄 끝 구절, 그리고 참고 카드의 측정 기록 줄. 해석 줄은 모두 '참고 — 예측 아님'이나 '측정 기록 … 예측이 아니다'와 함께 나가고, 이름표·구절·단계·점수의 예측력은 검증하지 않았다고 적습니다. 운영자가 과거 자료로 잰 숫자(예: 신용 긴축의 회귀 계수, 유가 상태별 평균, 지준·TGA 상관)는 그 날짜와 함께 정해 둔 글로 싣고, 이 사이트가 다시 계산하지 않습니다.
- **그래도 싣지 않는 것** — FRED 시리즈 쪽의 이용 조건 표시를 2026-10-30에 다시 확인했습니다.

  - **Moody's Baa − 10년(`BAA10Y`)** — FRED는 이 시리즈를 ICE·S&P의 'Pre-Approval Required'가 아니라 'Copyrighted: Citation Required'로 표시합니다. 그러나 시리즈 쪽 Notes에 실린 Moody's 고지는 Moody's의 사전 서면 동의 없는 복제·재배포를 막습니다. 또 BAA10Y는 FRED(세인트루이스 연은)가 Moody's Baa 회사채 금리에서 10년 국채 금리를 뺀 것이라 BAA10Y + DGS10(공개)으로 Moody's Baa 금리가 그대로 되살아납니다. 운영자는 이를 알고 받아들여, 비공개 월간 점검 줄과 같은 숫자 셋 — 수준(%p)·12개월 저점 대비(%p)·1990년 이후 분위(%) — 을 규칙 카드 '신용 스프레드'에 싣습니다(그래프는 없고, 날짜별 기록 `data/history/`에는 값을 빼고 충족 여부·고지·인용만 남깁니다 — 아래 'git 기록'). 값 곁에 '저점 대비·분위는 이 사이트의 계산값' 표시, FRED 권장 인용(출처는 스프레드를 계산한 'Federal Reserve Bank of St. Louis'), FRED 시리즈 쪽 Moody's 고지 원문(2026-10-30 확인, 글자 그대로)을 두고, 꼬리말에도 Moody's 고지를 싣습니다. 국면 모니터 표의 값 칸과 해석 줄의 Baa 부분에도 값이 나가고(고지는 꼬리말), 시세 띠에는 싣지 않습니다(고지가 곁에 보이지 않아서).
  - **나스닥100·Nasdaq CTA AI 지수의 낙폭(`NASDAQ100` · `NASDAQNQINTEL`)** — 'Copyrighted: Pre-Approval Required'인 채로, 신용 긴축 카드에 지수마다 252영업일 고점 대비 지금 낙폭 하나를 정수 %(예: −12%)로 싣습니다. 지수 값·12개월 고점·수익률·낙폭 시계열·그래프는 싣지 않습니다(자료 파일의 꼴 검사가 지수마다 −100~0의 정수 하나만 받습니다). 카드에 FRED 시리즈 쪽 저작권 표시(NASDAQ100 'Copyright © 2016, NASDAQ OMX Group, Inc.' — FRED 쪽의 깨진 'Â©'를 '©'로 고침, NASDAQNQINTEL 'Copyright © 2025, NASDAQ, Inc.')와 FRED 권장 인용(제목은 FRED 쪽 그대로 — 'NASDAQ-100', 'Nasdaq Consumer Technical Association Artificial Intelligence Index')을 함께 싣습니다.

- **복합 조건은 3값 논리**로 판정합니다. 한쪽 자료가 없어도 결론이 나는 경우만 충족·미충족으로 쓰고, 나머지는 '판정 불가'로 둡니다.

- **실업률 3개월 평균**은 빠진 달이 끼면 남은 2개월로 계산합니다(2025-10이 비어 있습니다). 직전 12개월의 3개월 평균이 9개 미만이면 '판정 불가'입니다. 값은 FRED의 현재 개정치로 다시 계산한 것이라 발표 당시 값과 다를 수 있습니다.

## 동작 방식

GitHub Actions가 예약 시각마다 돕니다([`daily.yml`](.github/workflows/daily.yml)).

1. **검사** — 공개 전 검사와 단위 테스트
2. **갱신** — 수집·판정 → 공개본(`data/public.json`) → 그래프 자료(`data/charts.json`) → 국고채 참고 자료(`data/ktb.json`) → 수급 참고 자료(`data/supply.json`) → AI 투자 참고 자료(`data/ai_invest.json`) → SEC 공시 조달(`data/sec.json`) → 신용 긴축(`data/credit.json`, sec.json을 읽는다) → 지준·재정(`data/liquidity.json`) → 연준 재무상태표(`data/fedbs.json`) → 기간 프리미엄 모형 대조(`data/tp.json`) → 단일종목 CDS(`data/cds.json`·`data/cds_days.json`) → 유가·에너지 참고 자료(`data/oil.json`) → 한국 시장(`data/korea.json`) → 상태 기록(`data/status.json`) → 새 산출물 포함 공개 전 검사 → 봇 커밋
3. **배포** — `site/`와 `data/`만 GitHub Pages로
4. **알림** — 갱신, 그래프 자료 생성, 국고채 참고 자료·한국 시장 자료 수신 중 하나라도 실패하면 실행을 실패로 끝냅니다(수급 참고·AI 투자·SEC 조달·신용 긴축·지준·재정·연준 재무상태표·기간 프리미엄 모형 대조·단일종목 CDS·유가·에너지 참고 자료는 실패해도 알림을 띄우지 않습니다 — [아래](#참고-미-국채-수급-두-지표). 이 참고 단계들은 각 2분 상한(한국 시장은 4분)이고, 갱신 잡의 상한 30분은 참고 단계 상한의 합 24분과 수집·생성 몫입니다)

실패한 날에는 직전 공개본이 그대로 남고, 페이지 첫 화면에 실패 배너와 마지막 성공 시각이 나옵니다. 그래프 자료만 실패한 날에는 직전 그래프가 남고 "그래프는 그 날짜 기준"이라고 표시합니다. 예정된 실행이 아예 빠진 경우에도 배너를 띄웁니다. 수신에 실패한 시리즈가 3개 이상이면(캐시로 대신한 것 포함) 그날은 기록하지 않습니다 — 오래된 캐시를 오늘 결과로 내보내지 않기 위해서입니다.

## 참고: 한국 국고채 금리

페이지의 **한국 국고채** 절(꼬리표 '채널 자료 · 규칙 판정 제외')은 위 규칙 점검과 성격이 다릅니다(2026-10-08 추가).

## 참고: 미 국채 수급 두 지표

'10년 기간 프리미엄' 카드의 읽는 법(흐름도 바로 뒤)에 **수급 참고** 칸이 있습니다(2026-10-14 추가, 제 결정). 흐름도에서 TFP(기간 자금 보상)로 가는 요인 가운데 둘 — 딜러 재고와 해외 공적 수요 — 의 실제 숫자입니다. **규칙이 아닙니다**: 규칙 수에 들지 않고, 충족·판정이 없고, 판정·공개본·그래프 스크립트는 이 파일을 읽지 않습니다.

| 지표 | 자료 | 빈도·단위 |
|---|---|---|
| 딜러 국채 순포지션(TIPS 제외) | 뉴욕 연은 Primary Dealer Statistics의 합계 시계열 `PDPOSGST-TOT` — `markets.newyorkfed.org` API에서 직접 | 주간(수요일 관측), 백만 달러(십억 달러로 바꿔 싣습니다) |

- **싣는 것** — 쪽마다 수준, 4주·52주 변화(28·364일 전 이하 마지막 관측 대비), 표본 시작(2019년, 자료가 그보다 늦게 시작하면 첫 관측 28일 뒤 — 각 줄에 그 해를 적습니다) 이후 모든 4주 변화의 p5·p95(28일 전 관측이 6일 넘게 멀면 그 변화는 세지 않고, 마지막 4주 변화도 그러면 비웁니다), 최근 5년 주간 그래프. 마지막 4주 변화가 p95 위나 p5 아래면 ⚠ 줄로 적고(4주 변화가 20개 미만이면 적지 않습니다), 2026-10-30부터 줄 끝에 운영자 월간 점검 [수급 구조]의 구절을 그대로 붙입니다 — 딜러 p95 위 '재고 급증(조달 압박·TFP 상승 쪽)', 딜러 p5 아래 '재고 급감', 수탁 p95 위 '수탁 급증', 수탁 p5 아래 '수탁 급감(매도 또는 민간 수탁 이전 — 단정하지 않음)'. 구절은 운영자 메모를 옮긴 참고이고 예측이 아닙니다(카드 고지에 적습니다). 딜러는 2022년 말(그 이하 마지막 관측) 이후 변화와, 거기에 Dallas Fed WP 2613 표 2의 TFP 계수(딜러 보유 십억 달러당 0.038bp)를 곱한 **산술 참고값**도 싣습니다 — 계수를 곱했을 뿐 이 사이트의 추정이 아니고, 판정에 쓰지 않습니다. 계산은 [`scripts/supply_fetch.py`](scripts/supply_fetch.py)가 하고 화면은 그 숫자와 정해 둔 문구를 그대로 보여 줍니다(원본 파이프라인 월간 점검과 같은 계산 — 코드는 가져오지 않고 따로 썼습니다).
- **수신** — 아침 갱신의 '수급 참고 자료 받기' 단계(뉴욕 연은 요청 1회 + FRED 요청 1회, 요청마다 20초, 단계 2분 상한). 뉴욕 연은 단일 시계열 주소의 **응답 형식은 이 저장소에서 확인하지 못해** 너그럽게 읽습니다: 날짜 필드(`asofdate`·`date` 등)와 `value`가 함께 있는 기록만, 키 필드가 있으면 `PDPOSGST-TOT`만, `*`(기밀)·숫자가 아닌 값은 버리고, 같은 날이 여러 시리즈 구분(series break)에 있으면 가장 새 구분의 값. 수준의 크기가 그럴듯한 범위 밖이면(단위를 잘못 읽은 경우) 닫힌 쪽으로 실패합니다.
- **실패하면** — 한쪽이 실패해도 다른 쪽은 갱신합니다. 실패한 쪽은 직전 값을 '받지 못함'(언제부터인지)과 함께 남기고, 직전 값이 없으면 화면에 '자료 없음' 한 줄만 나옵니다. 받은 자료가 직전보다 오래된 날짜이거나, FRED가 캐시로 대신한 것이면 받지 않습니다. 직전 파일이 깨져 있으면 이어 실을 값이 없는 것으로 봅니다(값은 매번 원자료 전체로 다시 계산하므로 잃는 것이 없습니다). 같은 내용이면 파일을 다시 쓰지 않습니다. 둘 다 실패하면 종료코드 1이지만 **실행을 실패로 끝내지 않습니다**(알림 메일 없음) — 규칙 판정과 무관한 참고 칸이고, 형식을 확인하지 못한 주소가 첫 실행부터 맞는다는 보장이 없어 매일 실패 메일이 오지 않게 했습니다. 실패는 그 단계의 로그와 페이지의 표시로 봅니다.
- **출처 표기** — 딜러 쪽은 SOFR과 같은 원칙으로 뉴욕 연은 이용약관의 기본 출처 형식(© 연도), "이 저장소가 계산한 값"이라는 표시(한·영), 관계없음 고지를 그래프 아래에 싣습니다. 수탁 쪽은 FRED 권장 인용(`supply.json`의 `source.citation`)과 그래프 출처 줄. FRED 시리즈 제목과 뉴욕 연은 통계 쪽 주소는 이 환경에서 접속하지 못해 **확인하지 못했습니다** — 첫 실행 뒤 시리즈 쪽과 대조합니다.
- 해외 공적 수탁이 줄었다고 곧 매도라고 볼 수는 없습니다(다른 보관 기관으로 옮겼을 수도 있습니다). 화면에도 같은 말을 적었습니다.

- **왜 이 칸들인가** — 원본 파이프라인에서 AI 주식 × 국채 상관을 실자료로 재 본 결과(2026-10-27): AI 지수의 금리 상관은 대부분 S&P 500의 것을 되풀이하고(두 지수 일간 수익률의 상관이 높다), 20영업일 상관은 우연 범위를 자주 넘나들며, S&P 500을 빼고 남는 몫은 대형 기술주 공통 요인과 겹칩니다. 그래서 규칙 카드 '주가-금리 60영업일 상관'을 바꾸지 않고, 상관은 이 화면에 나란히 그려 보기만 합니다. AI 투자 자체는 일간 상관보다 느린 수량(투자·조달·전력)으로 봅니다.
- **부호** — 상관은 주가 수익률 × **금리** 변화입니다. 양(+)이면 주가와 금리가 같은 방향, 국채 가격으로는 반대 방향입니다. S&P 500 선은 규칙 카드의 ρ60과 같은 계산이고(받은 시각이 달라 마지막 값이 하루 어긋날 수 있습니다), 테스트가 같은 값을 강제합니다.
- **재배포 제한** — S&P 500·Nasdaq 지수는 FRED에서 'copyrighted: pre-approval required'라 지수 값과 값을 되살릴 수 있는 파생값을 싣지 않습니다(예외는 신용 긴축 카드의 정수 낙폭 % 하나 — [위](#공개-원칙-2026-10-30-바꿈)의 회색 지대). 상관·부분상관과 b2 회귀의 계수·t값·일수·표본 날짜만 싣습니다(규칙 카드의 ρ60과 같은 원칙 — b2 표는 해마다 정해 둔 여덟 칸뿐이고, 계수 크기에 상한을 두어 지수 값 같은 큰 수가 섞이면 그 칸을 싣지 않습니다). 나머지는 공개 자료라 값과 FRED 권장 인용(`ai_invest.json`의 `sources[].citation`·`licence`, 시리즈 제목·출처는 2026-10-27, 사모대출 열 줄은 2026-10-30 시리즈 쪽에서 확인)을 싣습니다. 사모대출 아홉 줄(`BCNSDODNS` 밖)은 FRED에 이용 조건 표시가 없어 인용에 'Financial Accounts of the United States (Z.1)'를 넣고, 연준 이사회 자료의 공개 원칙에 기댄다는 고지를 붙입니다(`licence`: `board-public-domain (FRED unlabeled)`).
- **b2를 읽을 때** — AI 지수가 S&P 500보다 1%p 더 오른 날의 10년 금리 변화입니다. 해마다 따로 맞추는 까닭은, 묶으면 S&P 500 기울기를 여러 해에 하나로 강제해 b2가 낮게 나오기 때문입니다. 나스닥100 기술 섹터를 먼저 넣으면 AI 지수의 추가 몫은 거의 남지 않았습니다(2026-10-27 측정, 이 사이트가 다시 계산하지 않는 고정 문구) — 대형 기술주 공통 요인과 겹칩니다.
- **수신·실패** — 아침 갱신의 'AI 투자 참고 자료 받기' 단계(FRED 요청 30회, 전체 80초 상한 — 응답을 읽는 동안에도 보고, 단계 2분 상한. 사모대출 열 줄은 목록 끝이라 시간이 모자라면 그쪽부터 빠집니다). 칸마다 따로: 칸의 시리즈 가운데 하나라도 받지 못하면 그 칸만 직전 값을 '싣지 못함'(언제부터인지)과 함께 남기고, 직전 값이 없으면 '자료 없음'. 시리즈마다 끝 날짜가 다르면 값마다 그 날짜를 적고, 끝 날짜가 하나라도 직전보다 이르면 그 칸은 받지 않습니다. 재배포 제한 지수로 만든 칸은 새로 계산한 값과 이어 싣는 값 모두 꼴을 봅니다(상관은 값과 점이 −1~1, b2는 정해 둔 칸과 상한). 하나도 못 받으면 종료코드 1이지만 실행을 실패로 끝내지 않습니다(알림 없음). 계산은 [`scripts/ai_invest_fetch.py`](scripts/ai_invest_fetch.py), 화면은 [`site/ai_invest.js`](site/ai_invest.js)가 그 숫자와 정해 둔 문구를 글자로만 싣습니다.
- **긴 기간 그림** — '물가가 걱정이면 주가와 국채 가격이 같이, 고용이 걱정이면 반대로 움직인다'는 흔한 설명을 이 사이트의 두 규칙 조건으로 나눠 본 과거 평균입니다(2026-10-28 추가, 원본 파이프라인의 조사와 독립 재검을 거쳐). 1972~1997년은 대체로 음, 근원 PCE 전년비가 3%를 넘은 달이 없던 1998~2020년은 대체로 양이었지만 1972~1997년 안에서는 그 조건이 아닌 달도 비슷하게 음이라 조건과 시대의 차이가 겹쳐 있고, 실업률 상승 폭 조건이 맞은 달은 대부분 1998~2020년 안의 경기 침체 세 번이라 따로 떼어 보기 어렵고, 두 조건의 변화가 상관 부호의 변화보다 일정하게 앞서지도 않았습니다 — 화면에도 그렇게 적었고, 시대 경계는 사후에 고른 것이라고 밝힙니다. 조건은 자료 달 기준(발표 시차 없음, 현재 개정치)이고, 비교는 카드와 같은 함수·같은 반올림입니다. 주가-금리 상관 카드의 '읽는 법'에서 이 그림으로 잇습니다.
- **고신용 장기 스프레드** — 재무부 HQM 곡선(AAA·AA·A)이라 대형 기술 기업만의 값이 아니고, par끼리 견줍니다(현물을 쓰면 곡선 모양이 섞여 2025~26년 확대 폭의 절반가량이 그 효과였습니다). 30년 국채 금리는 2002-02-18~2006-02-09에 공식 발표가 중단돼(FRED 주석) 그 달들은 빼고 그립니다. 회사별 채권 스프레드(TRACE)와 ICE 등급별 지수는 유료이거나 재배포 금지라 싣지 않습니다. 회사별 CDS는 2026-10-30부터 DTCC 공개 거래 보고로 센 값을 따로 싣습니다([아래](#참고-단일종목-cds)).
- **읽을 때** — 사무실 건설 지출은 데이터센터를 따로 보이지 않아 일반 사무실이 줄면 증가가 희석돼 보입니다. 설비투자 / 내부자금은 비금융기업 전체 합계라 대형 기술 기업의 조달 방식은 보이지 않고, 100%를 넘는 일 자체는 드물지 않습니다(1985년 이후 분기의 약 3분의 2). 30년 − 10년 금리차는 AI 투자 때문인지 가릴 수 없습니다.

첫 화면의 점검표 위 **레짐 점검 참고** 절과 규칙 카드마다의 **해석 줄**(2026-10-30 추가, 제 결정)은 운영자의 비공개 월간 점검 알림 [레짐 점검]의 공개판입니다. 규칙의 충족 여부는 바뀌지 않고, 해석 쪽만 '참고 — 예측 아님'으로 붙습니다. 계산은 [`scripts/render_public.py`](scripts/render_public.py)가 `data/public.json`의 `regime` 절과 규칙마다의 `scenario`·`reading`으로 만듭니다(요청 없음 — 규칙 점검이 받은 자료만).

- **레짐 점검 참고** — 핵심 신호 n/m(이름표가 있는 규칙 중 충족한 수, 중립 규칙 둘은 따로), 국면 후보(S&P 500 13주 방향 × 미 10년 13주 변화의 사분면 — 완충 구간이면 직전 국면이 필요한데 그것은 사람이 정하는 값이라 공개 계산에서는 판정불가), ρ60과 'A′ 경보'(국면 후보 A인데 ρ60이 음), 근원 CPI<3%(Y/N), 전환 경계 자동 트리거(t2 IG OAS — ON/OFF만, t4 주가·10년 3주 동반 하락; t1·t3은 손으로), 손으로 보는 항목(주기와 내용만), 그 밖의 관측값(M2·본원통화·M2 유통속도·NDFI 잔액·명목GDP·원/달러·증권업 고용·실업률·근원 CPI − PCE). 읽는 법(이름표·핵심 신호·국면·경보·트리거의 정의)을 절 아래에 함께 싣고, 이름표의 정의 자체(시나리오 내용)는 운영자 메모라 싣지 않습니다.

### RMP 칸의 셈 규칙

카드의 RMP 칸에서 화면 글로 빼고 여기에 둔 셈 규칙입니다(2026-11-03 — 화면에는 숫자와 날짜, 차 한 줄만). 계산은 [`scripts/fedbs_fetch.py`](scripts/fedbs_fetch.py)의 `parse_plan`·`calc_view`·`rmp_window`·`bridge`·`floor_size`, 창마다의 셈은 `fedbs.json`의 `values`(`windows`·`checks`)에 있습니다.

- **읽는 계획 문장 꼴**(정해 둔 하나뿐): 'The Desk plans to conduct(또는 purchase) approximately $X billion in reinvestment purchases and' 다음에 'no reserve management purchases'(RMP 0) 또는 '(an additional) approximately $Y billion in reserve management purchases', 끝은 'over the noted monthly period.'. 다른 꼴(소액 시험 운영·운영 없음·쿠폰 배분 문장이 붙은 것·2019~2020년 'of bills' 꼴 등)은 **꼴 모름**이고 숫자를 짓지 않습니다 — 머리는 '계획 문장 꼴 모름 — 숫자를 짓지 않음', 누적은 '—(꼴 모름 창 n개)'. 금액은 페이지의 숫자 글 그대로입니다. 기간 날짜를 읽지 못한 행(꼴이 아님·없는 날·끝이 시작보다 이름·62일 넘음)은 버리고 그 수를 덧줄에, 같은 기간이 두 번이면 하나로(숫자가 다르면 꼴 모름), 그 달에 시작하는 기간이 여럿이면 숫자를 짓지 않고 **기간 여럿**으로 따로 셉니다 — 머리는 '그 달에 시작하는 기간이 여럿이라 숫자를 짓지 않음', 누적은 '—(기간 여럿 창 n개)', 표는 '기간 여럿 × n창'.
- **창**: 페이지 표의 기간(2026-11-03에 96개) 가운데 RMP 시작 창(2025-12-12 — 뉴욕 연은 운영 방침 2025-12-10)부터만 씁니다. 그 앞(2019~2025-11)은 다른 문장 꼴입니다. 창은 시작 달로 부르고, RMP 시작 달부터 마지막 시작 달까지 달마다 그 달에 시작하는 기간 하나입니다(없으면 '페이지에 없음' — 누적은 '—'). 마지막 창이 오늘을 품으면 '지금 창', 아직 시작 전이면(공지 뒤 주말 등) '다음 창', 끝났으면 '마지막 창 … · M월 창 계획은 페이지에 아직 없음'. 다음 달의 공지일(아래)이 지났는데 그 달 행이 페이지에 아직 없으면 창이 무엇이든 머리에 'M월 창 계획은 페이지에 아직 없음(공지일 MM-DD께 지남)'을 붙이고 그 날은 다음 날짜에서 뺍니다 — 여러 달이면 셋까지 'M월·N월 …', 넷부터는 'M월~N월 창 k달 …(첫 공지일 …)'(12달까지 셈). 머리의 이어진 창 수는 0이면 'n창째 0', 0이 아닌 같은 금액이면 'n창째 같은 금액', 한 창이면 '지난 창 Y에서 바뀜'. 묶음 표는 같은 RMP가 이어진 창끼리 한 줄이고 6줄까지입니다(그 앞의 창은 누적에만 듦).
- **다음 공지일**: 페이지 표의 다음 공지(Next Schedule Release) 칸에 날짜가 있으면 그 날(2026-11-03엔 모든 행이 비어 있었음 — 오늘부터 62일 안이거나, 그 날과 9영업일이 둘 다 지났을 때만. 칸 날짜만 지나고 9영업일이 아직 앞이면 9영업일), 없으면 운영 방침의 '매달 9영업일께'로 센 날에 '께'를 붙입니다. 덧줄은 공식 칸 날짜와 9영업일로 센 날을 나눠 적고, '공식 표의 다음 공지 칸은 비어 있음'은 그 칸이 정말 비었을 때만 씁니다. 영업일 = 평일 − 연방 공휴일(새해·MLK·대통령의 날·메모리얼·준틴스·독립기념일·노동절·콜럼버스·재향군인·추수감사절·성탄 — 일요일이면 월요일 대체, 토요일이면 대체 없음). 다음 FOMC는 이 카드의 주 칸과 같은 규칙입니다.
- **운영 결과 대조**: 뉴욕 연은 Markets API 국채 운영 결과(요청 1번 — RMP 시작 달 2025-12-01부터 오늘까지, 응답 2MB 상한)에서 결과가 나온 매입 운영의 받아들인 금액을 창마다 더합니다. 1억 달러 미만은 소액 시험 운영(small value exercise — 따로 공지)이라 빼고, 매각은 세지 않습니다(잔존 3년 이하 이표채로 옮긴 매입도 듦). 창 = 계획 페이지에 그 달에 시작하는 기간이 하나 있으면 그 공식 기간(시작~끝, 양 끝 포함), 없으면 운영일이 M월 9영업일 뒤이고 M+1월 9영업일 이하인 운영입니다(2025-12~2026-10 열한 창은 둘이 같았음). 이웃 창이 겹치거나 사이에 영업일이 비면(반 달씩 나눈 행 같은 꼴 — 페이지의 2020-06~2021-02) 모든 창을 9영업일 규칙으로 잡습니다 — 빈 날의 운영이 어느 창에도 들지 않는 일이 없게(마지막 창은 다음 달 창과의 사이도 봄). 공식 기간 행의 문장이 꼴 모름이어도 기간은 경계로 씁니다. 그 달 MBS 상환 = `WSHOMCB`(전달 25일 이후 첫 수요일) − `WSHOMCB`(그 달 25일 이후 첫 수요일) — 지니메이 20일·패니메이·프레디맥 25일 상환이 한 번씩 듭니다. 25일이 주말·연방 공휴일이면 다음 영업일부터 셉니다(성탄이 수요일인 해 — 2024·2030·2041 — 의 12월은 다음 수요일). 대조 = 보이는 소수 한 자리의 매입 − 상환이고, 화면에는 끝난 창의 '대조 − 계획 RMP' 범위 한 줄만 둡니다(2026-11-03: 끝난 10창 −0.3~+0.2bn). 창마다의 운영 수·합·운영일·상환 수요일·대조값은 `fedbs.json`의 `values.checks`에 있습니다. 끝나지 않은 창은 상환과 견주지 않습니다.
- **한계**: 대조는 공식 수치가 아니라 이 사이트의 셈입니다. 재투자는 기관채·MBS는 그 달 예상 상환, 기관 CMBS는 전달 실제 상환 기준이라(뉴욕 연은 FAQ) MBS는 예상과 실제 상환이 어긋날 수 있고, 기관 CMBS 상환은 `WSHOMCB`(= 기관 MBS + 기관 CMBS)에 들어 있지만 재투자가 한 달 늦게 따라오며(작음), 기관채 상환은 `WSHOMCB`에 없어 빠집니다(H.4.1 연방 기관채 보유 약 2.3bn, 2026-07~10 변화 없음). 공식 기간이 없는 달의 창 경계는 9영업일 규칙의 근사입니다.
- **RMP 시작 뒤 지준**: 수요일 수준(H.4.1) 일곱 시리즈(`WRBWFRBL`·`WDTGAL`·`WLRRAOL`·`WLRRAFOIAL`·`WSHOBL`·`WSHOMCB`·`WCICL` — 나눔 칸이 받는 것이라 새 요청 없음)가 모두 있는 수요일 가운데 RMP 시작 앞 마지막 네 날과 마지막 네 날, 둘 다 이어진 네 주일 때만 셉니다(한 주라도 빠지면 비움). 네 주 평균의 차 = 연준 단기채+MBS · 재무부 현금(TGA) · 현금 통화 · 역레포(익일물 + 해외 공적) · 그 밖(연준 이표채·TIPS·대출·기타 부채 등의 나머지)이고, 부호는 지준 쪽, 보이는 정수끼리 합이 맞게 '그 밖'이 반올림 차를 받습니다. 한 주 끝점이 아니라 네 주 평균인 까닭: 2026-11-03 실자료로 2025-12-10에서 2026-10-28로 셈하면 지준 −78.5bn, 출발을 한 주 앞 12-03으로 옮기면 +17.1bn — 재무부 현금 한 주(12-10에 805.8bn, 10-28에 1,015.6bn)에 부호까지 바뀝니다.
- **규칙 하한의 달러 크기**: 규칙 하한(9.0% — `regime_rules.TH['reserves_gdp_low']`) × RMP 시작(2025-12-12)이 든 분기의 명목 GDP와 × 마지막 분기 명목 GDP(현재 개정치 — 지준 칸과 같은 분기). 이 사이트 규칙 카드의 추정값이고 연준이 말하는 'ample'의 기준이 아닙니다(단기자금 여건은 SOFR − IORB·상시 레포 칸).

SEC 공시는 실행마다 68개를 모두 받습니다(공시는 분기마다지만 원 응답을 남기지 않기 때문). 칸마다 따로 실패합니다(응답의 꼴이 뜻밖이면 — 예: 사실 목록이 목록이 아님 — 그 묶음만 '계산할 자료가 모자람'): 흐름 태그 하나를 받지 못하면 기업별 조달·조달 흐름이, 잔액 태그 하나를 받지 못하면 재무상태 잔액만 직전 값과 '받지 못함'으로 남습니다(흐름이 실패해도 잔액 태그는 받습니다 — 다만 SEC가 거절하면 거기서 모두 멈춤). 연락처가 없으면 세 칸 모두 '연락처 미설정'. 회사채 공급 대 흡수도 다섯 시리즈 가운데 하나라도 받지 못하면 그 칸만 직전 값과 '받지 못함'입니다. 계산은 [`scripts/credit_fetch.py`](scripts/credit_fetch.py)·[`scripts/sec_fetch.py`](scripts/sec_fetch.py), 화면은 [`site/credit.js`](site/credit.js) — 조달 흐름·재무상태 잔액은 `data/sec.json`의 `flow`·`bal` 칸을 화면이 바로 읽고(`credit.json`에 옮기지 않음), 그 칸이 없는 옛 파일이면 그 줄을 두지 않습니다.
- **짝 테스트용 순수 함수** — 비공개 원본과 같은 산식인지는 비공개 쪽 테스트가 봅니다. 그쪽이 부르는 함수: `sec_fetch.flow_calc(quarterly, filled)`(회사 키 → 칸 → 분기 끝 → 달러, filled = 회사 키 → 칸 → 0으로 채운 분기 끝들 — '줄 없음' 셈에), `sec_fetch.bal_calc(facts)`(회사 키 → 태그 → `[끝, 값, 낸 날, 양식]` 시점 사실 목록), `credit_fetch.bond_flow(S)`(FRED ID → `[(분기 첫날, 연율 백만 달러)]`) — 셋 다 values dict를 돌려주고 요청·파일이 없습니다.
- **출처 표기** — FRED 권장 인용(NFCICREDIT는 'Copyrighted: Citation Required' 시카고 연은 자료라 그 고지를 함께), Nasdaq 지수는 재배포 제한 고지와 FRED 쪽 저작권 표시·FRED 권장 인용, EBP는 논문 인용·출처 줄·공공 영역 고지(이사회 인장 없음), CMDI는 뉴욕 연은 기본 출처 형식·계산값 표시(한·영)·관계없음 고지·논문 인용, SEC는 "Source: SEC EDGAR XBRL API (data.sec.gov); site calculations"(인장·로고 없음).

### 연준 인물 — 새 발언 자동 분류

2026-11-04부터(제 결정 — 확인 단계 없이 자동, 인용 포함) 페이지 머리의 띠 **'최근 발언 — 기준선 대비(자동 분류)'**(사람을 가리지 않고 최신 10개)와 사람 파일의 칸 **'새 발언 — 기준선 대비(자동 분류)'**(최신 8개, 나머지는 접어 둠)에 새 발언을 그 사람의 기준선에 견준 결과를 싣습니다. **자동 분류**입니다 — 언어 모델(AI)이 기사를 읽고 운영자가 정리한 기준선(기준일 · 사람마다 확인함/초안 표시)에 견준 결과이고(판정 · 까닭 · 주제 · 인용 고르기 모두 — 정해 둔 계산인 이 사이트의 '규칙'이 아닙니다), 사람 확인 없이 매일 올라갑니다. 틀릴 수 있고, 예측이 아닙니다. 그 사람의 발언이 파일에 없으면 파일이 담은 기간(시작일부터 기준일까지)을 그대로 말하고, 상한으로 덜어 낸 파일이면 그 앞의 발언은 싣지 않았다고 덧붙입니다.

## 참고 카드와 운영자 비공개 점검의 다른 점

같은 산식을 옮겼지만, 공개판은 사람이 넣는 값이 없고 칸마다 따로 실패하도록 만들어 아래는 일부러 다르게 둡니다.

- **연간 한도**는 코드의 표(`korea_issuance.ANNUAL_LIMITS`)로 둡니다 — 2026년: **225.7조원**([2026년 국고채 발행계획 및 국채시장 정책방향](https://mofe.go.kr/nw/nes/detailNesDtaView.do?searchBbsId1=MOSFBBS_000000000028&searchNttId1=MOSF_000000000076306&menuNo=4010100), 2025-12-26 보도). **손볼 일**: 추경 등으로 재정경제부가 연간 계획을 고치면('…국고채 발행계획 수정' 보도자료 — 2025년에도 있었다) 그 보도자료의 한도·날짜·주소로 표를 사람이 고칩니다. 코드는 수정 계획을 찾지 않아, 고치기 전까지 화면은 옛 한도 대비 비율을 그대로 냅니다(화면에 한도의 보도 날짜가 함께 나옵니다). 그해 한도가 표에 없으면 화면에 '연간 한도 미등록'만 쓰고 추정하지 않습니다. 화면의 '보도자료 발행 규모 합계'는 달마다 다음 달 보도자료 참고표에 적힌 보도 시점 값(그달 말 전에 집계 — 2026년 2월 보도자료는 1월 값을 '예상'으로 적었다)을 그대로 더한 것입니다. 뒤에 확정되는 20년물 비경쟁인수(Ⅱ·Ⅲ)와 모집분이 빠져 있어 재정경제부가 밝힌 누계보다 작을 수 있습니다(2026년 상반기: 이 합 123.1조원, 7월 보도자료의 '누적 124.1조원'). 재정경제부의 누적 문구는 일부 보도자료에만 있어 읽지 않습니다. 보도자료에 실적이 적힌 달만 더하고, 1월부터 빠진 달이 있으면 한도 대비 비율을 내지 않습니다(빠진 달을 화면에 적음).
- 보도자료 목록은 쪽마다 10건이고 경과물 모집 공고도 함께 걸려, 첫 쪽에 월별 계획이 8건쯤만 남기도 합니다(2026-10-28: 10월~3월). 1월 실적은 그해 2월 계획에만 적히므로, 보고 연도(가장 새 계획 달의 한 달 전이 속한 해 — 1월 계획이면 전년)의 2월 계획이 첫 쪽에도 저장된 달에도 없고 첫 쪽 가장 오래된 달이 그보다 늦을 때만 둘째 쪽(`pageIndex=2`)을 한 번 더 읽습니다(둘째 쪽은 그 2월 계획부터의 달만 — 더 오래된 계획은 그해 합계에 쓰이지 않아 읽지 않습니다). 2월부터 저장돼 있는 평소에는 읽지 않고, 둘째 쪽을 못 읽어도(접속·형식·시간 예산) 묶음은 실패로 두지 않고 Actions 기록에 한 줄(`ktb_plans page2: 오류 이름`)만 남깁니다. 그 2월 계획을 계속 못 읽으면 다음 해 2월 계획이 나올 때까지 실행마다 둘째 쪽을 다시 읽습니다(목록 요청 하나).
- 발행계획은 최근 12달, 매입·교환 결과는 최근 24건을 둡니다(2026-10-29 — 매입·교환이 한 목록이라 12건이면 달마다 둘씩 반년 치뿐이었다). 한 번 실행에서 새로 읽는 것은 가장 새 보도자료(정정 확인) + 아직 없는 것 최대 5건, 결과는 종류별로 가장 새 것 + 아직 없는 것 2건이고, 나머지 달·건은 전에 읽은 값을 둡니다(첫 실행에서 시간 예산이 모자라면 다음 실행들이 채웁니다). 읽는 순서는 아직 없는 공고(새 것부터)가 먼저 — 결과는 매입·교환을 번갈아 — 이고, 이미 읽은 가장 새 공고 다시 읽기는 맨 끝이라 시간이 모자라면 다시 읽기가 빠지고 전에 읽은 값이 남습니다(새 공고를 하나도 못 읽고 창이 끝나면 그 묶음은 `timeout` 실패로 표시하되 전에 읽은 값은 그대로 둡니다)(2026-10-29 — 다시 읽기가 앞에서 2월 계획을 밀어내고 교환 결과는 매입 뒤에서 한 번도 읽히지 않았다).
- 입찰 예정액은 한국은행 발행공고의 경쟁입찰 금액을 날짜·만기에 맞춰 표시합니다. 결과가 나오면 결과 공고의 입찰금액을 우선합니다. 금액 링크는 해당 원문으로 연결되며, 확인되지 않은 예정액은 0으로 채우지 않고 발행공고 목록을 연결합니다. 일반 국고채 경쟁입찰만 추출하고 교환·모집·물가채 결과는 포함하지 않습니다. 경쟁입찰 구역은 보통 '(1) 경쟁입찰 … (2) 일반인입찰'이고, 일반인입찰이 없는 공고(50년물 등)는 번호 없이 'ㅇ 경쟁입찰 … - 입찰일 … - 발행예정금액 …' 뒤 다음 항목까지로 읽습니다(2026-10-14 — 10-16 50년물 공고가 이 꼴이라 예정액 묶음 전체가 실패했다). 그래도 형식이 다른 공고 하나는 그 공고만 건너뛰고(그 회차는 금액 대신 공고 목록으로 연결하고 화면에 '발행공고 n건을 읽지 못했습니다'를 표시), 같은 공고를 전에 읽었으면 그 값을 둡니다. 입찰 결과 공고도 같은 방식으로 공고마다 따로 읽습니다(2026-10-26 — 10-16 50년물 결과 공고가 '가중평균낙찰금리' 대신 '낙찰금리'를 써서 10-17부터 결과 묶음 전체가 실패했다).

**실패 처리**: 제목·단위·빈도 변경, 중복·미래 날짜, 범위 밖 수치, 선물 순매수 합계 불일치, 응찰률 산술 불일치 등을 거부합니다. 열두 자료 묶음(금리·신용·단기자금 차트 3, 선물 2, 일정·결과·예정액 3, 발행계획·매입/교환 2, 통화안정증권 결과·발행 계획 2)은 각각 마지막 성공 자료를 보존하며 수신 실패 상태·확인 시각을 노출합니다. 하나라도 실패하면 종료코드 1로 Actions 알림에 반영합니다. 발행공고는 한 건도 새로 못 읽을 때만 묶음 실패이고(원인에 따라 `timeout`·`unavailable`(접속)·`unreadable_notices`(형식)), 건너뛴 공고는 공고 번호와 고정 사유 코드(`pdf_link`·`no_competitive_section`·`ambiguous_fields`·`http_404`·`network`·`parse` 등)만 `korea.json`의 `feeds.offerings.skipped`·`feeds.auctions.skipped`(발행계획·매입/교환은 `feeds.ktb_plans.skipped`·`feeds.ktb_ops.skipped` — `field_changed`·`sum_mismatch`·`month_mismatch`·`attachment`·`pdf_shape`·`date_mismatch` 등, 매입·교환 목록 한 종류가 비면 공고 번호 대신 종류 이름과 `no_notices` — 화면은 이것을 못 읽은 공고 건수에 넣지 않고 '교환(매입) 입찰 결과 목록에서 공고를 찾지 못했습니다'로 따로 적음)와 Actions 경고(실행을 실패로 만들지 않음)에 남깁니다(2026-10-14 — 전에는 공고 하나가 양식이 달라도 8건 전부를 버렸다). 공고 원문·담당자 정보·원격 HTML은 공개본에 넣지 않습니다. 발행계획은 그달 8일부터 그달 계획이 없으면 `stale`(7일까지는 지난달 계획까지 둠 — 계획은 대개 전달 말, 늦으면 그달 1~3일에 나온다. 이전 자료 유지)이고, 매입·교환은 달마다 있지 않아 날짜로 묵음을 따지지 않습니다. 이 두 묶음은 평소 가장 새 공고 하나만 다시 읽으므로, 못 읽은 공고가 모두 전에 읽은 것이고 사유가 일시 오류(`network`·`timeout`·`http_408`·`http_429`·`http_5xx`)뿐이면 묶음 실패로 두지 않고 전에 읽은 값을 둡니다(사유 코드·Actions 경고는 남음, `http_404` 같은 오류와 새 공고의 실패는 그대로 실패). 두 묶음은 다른 여덟 묶음(묶음당 45초) 뒤에 각 60초 창으로 돌고(전체 180초 안 — 재정경제부는 쪽마다 3.5~4초가 걸린다), 예산을 다 쓰면 남은 보도자료는 `not_tried`로 남기고 전에 읽은 값을 둡니다. 통화안정증권 결과(`msb`)는 마지막 입찰이 21일보다 묵으면 `stale`(평소 주 두 번 — 설·추석 연휴의 간격 14일보다 길게), 저장분보다 옛 입찰로 되돌아가면 `regressed`이고, 공고마다 따로 읽어 못 읽은 공고만 고정 사유 코드(`date_mismatch` — 목록·공고 제목·본문 첫 줄의 입찰일이 서로 다르거나, 공고 제목·본문 첫 줄의 꼴이나 요일이 날짜와 맞지 않음, `tenor_changed`, `rate_kind` — 1년 미만인데 수익률·1년 이상인데 할인율, `field_changed`, `out_of_range` — 낙찰액 > 응찰액·낙찰기관 > 응찰기관·낙찰금리가 응찰금리 범위 밖 등, `future`)로 `feeds.msb.skipped`에 남깁니다. 목록에서 제목 꼴이나 요일이 맞지 않는 줄은 결과 공고로 보지 않아 코드 없이 빠집니다(다른 목록 파서와 같음 — 2025-09 ~ 2026-11 목록 100건에는 없음). 발행계획·매입/교환처럼, 못 읽은 공고가 모두 전에 읽은 것이고 사유가 일시 오류뿐이면 묶음 실패로 두지 않고 전에 읽은 값을 둡니다. 같은 입찰일·만기의 공고가 둘이면(정정 공고) 번호가 큰 것을 두고 밀린 번호는 다시 읽지 않습니다. 다른 열 묶음 뒤에 50초 창으로 돌아(전체 180초 안), 앞 묶음이 시간을 다 쓴 날엔 목록이나 새 공고를 못 읽어 이 묶음만 `timeout`이고 전에 읽은 값을 둡니다. 통화안정증권 발행 계획(`msb_plans`)은 국고채 발행계획과 같이 그달 8일부터 그달 계획이 없으면 `stale`(7일까지는 지난달 계획까지), 되돌아가면 `regressed`이고, 계획마다 따로 읽어 못 읽은 계획만 `month_mismatch`(제목의 달과 PDF 첫 문장의 달이 다름)·`sum_mismatch`(총액 ≠ 경쟁입찰 + 모집 최대, 0.1조원 넘게)·`field_changed`·`out_of_range`·`pdf_link`(첨부 PDF가 하나가 아님)·`pdf_shape`·`future`로 `feeds.msb_plans.skipped`에 남깁니다. 중도환매 칸만 못 읽으면(총액 문장과 표의 합이 다름, 총액 문장이 둘 이상, 표에서 금액을 못 읽음 또는 읽은 금액 수가 표의 입찰시간 수와 다름, 0~30조원 밖) 계획은 싣고 그 칸만 '원문 확인'입니다. 결과 묶음 다음에 40초 창으로 돕니다.

`korea.json`에 더한 칸: `ktb_plans`(달마다 `month`·`published`·`competitive_100m`·`tenors[{tenor, amount_100m}]`·`long_share_pct`·`y30_share_pct`·`stated_prev_change_100m`·`stated_plan_change_100m`·`stated_plan_change_unread`(true/false)·`buyback_plan`/`exchange_plan`(`{amount_100m, dates}` 또는 null)·`prev_actual`(`{month, amount_100m}` 또는 null)·`source_url`), `ktb_ops`(`kind`(`buyback`·`exchange`)·`date`·`offered_100m`·`bids_100m`·`bid_cover_pct`·`awarded_100m`·`source_url`), `ktb_summary`(`latest_month`·`prev_month_change_100m`·`progress{year, months, through, missing, actual_100m, limit_100m, limit_published, limit_source_url, pct}`). 금액은 모두 억원입니다.

`korea.json`의 통화안정증권 칸(2026-11-09): `msb`(새 것부터 — `id`(한국은행 공고 번호)·`date`·`tenor`(`91일`·`1년` 꼴)·`offered_100m`·`bids_100m`·`bidders`·`awarded_100m`(억원 — 공고의 0.01조원 단위 값을 옮김)·`rate_kind`(`discount` 낙찰할인율 / `yield` 낙찰수익률)·`rate_pct`·`bid_cover_pct`(이 사이트의 계산값)·`source_url`, 정정 공고에 밀린 원 공고가 있으면 `replaces`(그 번호들 — 다시 읽지 않으려고 적어 둠))와 `msb_summary`(`months[{month, count, offered_100m, bids_100m, awarded_100m, short, through?}]` — `short`는 응찰액이 발행예정액보다 적은 입찰 수, `through`는 끝나지 않은 이번 달의 마지막 입찰일)와 `msb_plans`(달 순서 — `id`·`month`·`published`(목록의 등록일)·`total_100m`(모집 최대 기준)·`competitive_100m`·`offer_min_100m`·`offer_max_100m`·`redemption_100m`(중도환매 예정, 표가 없으면 null)·`redemption_unread`(표는 있는데 총액 문장과 표의 합이 다르거나 금액을 못 읽음 — 화면은 '원문 확인')·`source_url`).

- **새 노트 쓰기** — `notes/YYYY-MM-DD-영문-소문자.md`를 쓰고 `python -X utf8 scripts/notes_build.py`를 돌려 `data/notes.json`을 함께 커밋합니다(`--check`는 쓰지 않고 비교만 합니다). 둘이 어긋난 채 올리면 테스트가 막습니다. 그 테스트는 아침 워크플로의 앞 단계라, 배포뿐 아니라 다음 날의 FRED 갱신도 함께 멈춥니다.
- **받는 문법** — 머리말(제목 · 날짜 · 출처 · 원문 제목 · 원문 주소 · 저자 · 발행일 · 읽는 시간 · 난이도 · 한 줄 결론), `##`·`###` 제목, 문단, 목록, 표, `**굵게**`, `[글](https://…)`, `::질문` 아래 번호 목록 3개. 그 밖의 것(원시 HTML, 인용문, 코드, 그림 `![]`, 맨 주소, https가 아닌 링크, 보이지 않는 글자)은 파일 이름과 줄 번호를 찍고 멈춥니다.
- **그림 세 종류** — ① `::사이트그래프 <규칙 키> | 캡션`: 사이트가 평일 아침마다 받는 규칙 그래프를 그대로 싣습니다. ② 펜스 `도식` 안의 JSON: 직접 그리는 개념도입니다(수치 축 없음, 화면 읽기용 설명 `alt` 필수). ③ `::정적그래프 <그래프 키> | 캡션`: `scripts/notes_charts.py`로 받아 둔 공개 통계(`data/notes_charts.json`)를 연 단위로 그립니다.
- **정적 그래프의 자료 조건** — FRED 계열 쪽의 저작권 표시가 "Public Domain: Citation Requested"나 "Copyrighted: Citation Required"이고 마지막 값이 2025년 이후일 때만 싣습니다. "Pre-approval Required"이거나 표시를 읽지 못하면 스크립트가 파일을 쓰지 않습니다. 그래프 아래에 출처(FRED 경유)·계산한 선 표시·받은 날을 적습니다. 이 스크립트는 손으로 돌리며 아침 워크플로에서는 돌지 않습니다.
- **테스트** — 아침 테스트에 함께 돕니다: `test_notes_build.py` 50개 · `test_notes_charts.py` 21개 · `test_notes_site.py` 22개, 그리고 가짜 DOM 위에서 실제 노트를 그려 보는 `node --test scripts/test_notes_render.cjs` 21개.

## 저녁판(시범)

평일 저녁, 텔레그램 공개 채널 여러 곳이 함께 다룬 주제를 규칙으로 골라 보여 주는 화면입니다(`#evening`). 아침 점검표의 규칙 판정과 무관한 참고 자료이고, 금리의 방향이나 강도, 매매 판단을 내지 않습니다. 2026-10-08에 시범으로 열었고, 낱말 사전과 점수 기준은 시범 동안 바뀝니다.

### 싣는 것과 싣지 않는 것

- 싣는 것: 미리 정한 낱말 사전의 낱말과 그 낱말을 쓴 채널 수, 출처 라벨, 정해 둔 문구, 숫자와 단위, 글을 올린 시각, `https://t.me/<채널 이름>/<글 번호>` 꼴의 원문 링크입니다.
- 읽을거리를 늘리려고 2026-10-08 저녁부터 아래 것도 싣습니다. 어느 것도 채널 글의 글자가 아닙니다.
  - 글마다: 글 길이 구간(200자 미만 '짧은 글' · 700자 이상 '긴 글' · 그 사이 '보통 길이'), 그 글에서 걸린 사전 낱말의 수, 그림·파일이 붙었다는 표시입니다. 그림·파일 자체와 글자 수는 싣지 않습니다.
  - 묶음마다: 두 곳 이상이 직접 쓴 낱말과 그 채널 수(전달 글은 세지 않습니다), 묶인 글의 수, 첫 글과 마지막 글의 시각입니다. 대표 낱말이 A·B급이고 직전 판에도 있었으면 그때의 채널 수를 함께 적습니다. 낱말이 같다는 뜻일 뿐 같은 묶음이라는 뜻은 아닙니다.
  - 낱말 풀이: 이 사이트가 직접 쓴 한 줄(60자 안쪽)이고, 그 판에 나온 낱말의 것만 싣습니다. 낱말의 뜻만 적으며 그 글의 내용·시세·전망·평가는 담지 않습니다. 나라를 밝히지 않은 지표(CPI·GDP 등)는 미국 지표로 세므로 풀이가 그 글이 다룬 나라와 다를 수 있습니다.
  - 풀이 옆의 바깥 링크: 규칙에 적어 둔 주소 50개(도메인 19개)뿐입니다. t.me가 아닌 링크는 이것과 삭제 요청 양식뿐입니다. '공식 자료'는 정부·중앙은행·국제기구의 쪽입니다(통계 쪽이 아니라 기관의 첫 쪽일 때도 있습니다). '시계열'과 '문서 모음'은 세인트루이스 연은이 통계와 문서를 모아 싣는 쪽(FRED · FRASER)이고, 그 가운데 변동성 · 신용 스프레드 · 미 소비심리 · 모기지는 민간 기관이 내는 지표입니다. 채널 글이 가리킨 주소는 싣지 않습니다.
- 낱말을 늘어놓을 때는 글에 나온 순서가 아니라 채널 수 · 등급 · 가나다 순으로만 놓습니다. 낱말 목록이 글의 요약처럼 읽히지 않게 하려는 것입니다.
- 숫자는 두 곳 이상이 같은 낱말 곁에 똑같이 쓴 것만 싣습니다. 예외는 '속보형·개인 채널이 혼자 쓴 글' 절 하나이고, 그 절의 숫자는 한 곳만 쓴 숫자라고 화면에 적습니다. 이 절에는 숫자 없이 낱말만 있는 줄도 실립니다(첫 두 줄에 사전 낱말이 있는 글, 채널당 5줄까지).
- 싣지 않는 것: 채널 글의 문장·첫 줄, 사진·표 그 자체, 링크 카드의 기사 제목입니다. AI 요약 문장은 채널 글의 문장이 아니라 AI가 자기 말로 쓴 것이며, 원문과 길게 겹치면 싣지 않습니다. 규칙판(고르기·묶기·점수)은 LLM을 쓰지 않습니다. 'AI 요약' 표시가 붙은 문장만 운영자 PC에서 AI가 따로 씁니다(아래 'AI 요약').
- 채널 글의 글자는 공개되는 것(`data/*.json`, 화면, Actions 로그) 어디에도 나가지 않습니다. 원문은 실행기의 작업 폴더(`.work/evening/`)에만 있고 커밋·아티팩트·로그에 넣지 않습니다. 공개 JSON의 모든 문자열이 허용 목록(사전 낱말 · 정해 둔 문구 · 규칙에 적힌 풀이와 주소 · 숫자와 단위 · 시각 · 길이 구간 이름)으로 다시 조립되는지를 게시 전에 두 번 검사합니다. 화면도 낱말과 풀이를 사전의 지문과 견줘 한 번 더 거릅니다.
- 판이 크기 상한(36KB)에 걸리면 낱말 풀이 → 단독 줄 → 나머지 표 순으로 덜어 내고, 덜어 낸 판에는 알림 줄을 붙입니다.
- 낱말과 숫자만으로는 글의 뜻을 잘못 짚을 수 있습니다. 무슨 내용인지는 링크를 눌러 원문에서 읽어야 합니다.

### AI 요약 (시범)

꼭 볼 것과 일부 항목에는 'AI 요약' 표시가 붙은 한두 문장이 실립니다. 이 문장은 채널의 글이 아니라 AI(Claude)가 쓴 것입니다.

- **무엇을 읽고 무엇을 쓰는가** — 게시된 규칙판에서 꼭 볼 것 전부와, 채권·애널 그룹 원천 채널 두 곳 이상이 직접 쓴 항목을 합쳐 6개까지 고릅니다. 항목마다 그 채널들의 전달 아닌 글을 3건까지(글마다 1,500자까지) 읽고, 무슨 일인지를 한국어 한두 문장(140자 이하)으로 씁니다. 개인·속보형 채널의 글과 전달 글은 읽히지 않습니다. 읽을거리가 300자에 못 미치는 항목은 쓰지 않습니다.
- **어디서 도는가** — GitHub Actions가 아니라 운영자의 PC에서 돕니다. 고르는 일(규칙판)은 지금처럼 LLM 없이 Actions가 하고, PC는 고른 글의 본문을 텔레그램 웹 미리보기에서 한 번 더 받아(채널마다 한 번, 3초 간격, 20요청까지) 도구를 모두 끈 Claude Code에 건넵니다(`--safe-mode --tools ""`, 새로 만든 빈 폴더, 꼭 필요한 환경 변수만). 글을 건네기 전에 매번 원문 없는 점검 호출로 도구·MCP·스킬이 비어 있는지, 물음 말고 다른 것이 모델에 실리지 않았는지(입력 토큰 수)를 확인하고, 하나라도 어긋나면 글을 건네지 않습니다. 채널 글의 본문은 PC의 메모리에만 있고 파일·로그·저장소에 남기지 않습니다. 다만 그 본문이 요약을 위해 Anthropic의 모델로 전송된다는 점은 분명히 적어 둡니다.
- **검사** — 문장마다 여섯 가지를 봅니다: 꼴(평서문 한두 문장, 주소·@·채널 이름 없음), 정해 둔 권유·전망·평가·광고 표현, 베낌(원문과 20자 이상 이어 겹치거나, 글자 3-gram의 60% 이상이 한 글에 있거나, 조사만 바꿨거나, 여러 글의 긴 토막을 이어 붙인 문장), 숫자(원문에 같은 단위로 있는가, '예상·전월·전년'이 붙은 숫자를 그 말과 함께 썼는가), 낱말(그 항목과 읽힌 글의 낱말인가, 방향·결정을 글과 다르게 쓰지 않았는가), 이름(사람 이름·영문 약어가 읽힌 글에 있는가). 하나라도 걸린 문장은 버리고 사유별 개수만 남깁니다. 걸린 문장이 있어도 규칙판은 그대로 나갑니다.
- **틀릴 수 있습니다** — 검사는 정해 둔 꼴만 잡습니다. 숫자도 사전 낱말도 없이 뜻을 틀리게 옮긴 문장, 다른 말로 쓴 전망은 걸러 내지 못합니다. 짧은 어구는 원문과 겹칠 수 있습니다. 사람이 확인한 뒤 싣는 것이 아니라 검사를 통과하면 바로 실립니다. 문장은 길잡이일 뿐이니 원문 링크에서 확인해 주세요.
- **약관과의 긴장** — 텔레그램 약관에는 플랫폼에서 얻은 자료를 AI·기계학습에 쓰는 것을 제한하는 조항이 있고, 공개 채널이라는 예외를 두지 않습니다. 이 기능은 그 조항과 긴장 관계에 있습니다. 그래서 읽는 범위를 채권·애널 원천 채널의 글 몇 건으로 좁히고, 본문을 저장하지 않고, 원문을 옮겨 적지 않는 검사를 두었으며, 채널 운영자가 요청하면 그 채널을 목록에서 내립니다(아래 '삭제·정정 요청').
- **PC가 꺼진 날** — PC가 꺼져 있거나, Claude 로그인이 만료됐거나, 점검에서 멈췄거나, 문장이 모두 검사에 걸린 날에는 문장 없이 규칙판만 나갑니다. 예약 작업은 평일 17:45·23:30과 이튿날 07:30에 돌고(늦게 다시 계산된 판을 따라가기 위해서입니다), 달라진 것이 없으면 채널도 모델도 다시 부르지 않습니다.
- **내리는 방법** — 저장소 변수 `EVENING_ENABLED`를 끄면 PC도 규칙판 실행을 시작하지 않고 채널을 읽지도 모델을 부르지도 않으며, 올라가 있는 문장은 다음 실행에서 빈 것으로 바뀝니다. 완전히 내릴 때는 변수를 끄고, 내리기 실행(`evening.yml`의 takedown)을 돌리고, PC의 예약 작업을 지웁니다(`Evening-Summary.ps1 -Unschedule`). 예약 작업을 지우면 같은 작업이 돌리는 연준 인물 새 발언 게시도 — 내리기까지 — 멈춥니다([위](#연준-인물--새-발언-자동-분류)). 저녁판만 내리고 그 게시는 두려면 변수만 끄고 작업은 둡니다.
- **파일** — `data/digest_picks.json` 하나(가장 최근 한 판의 문장만). 코드는 `scripts/evening/evening_llm.py`(고르기·받기·묻기), `digest_picks.py`(형태와 문장 검사), `picks_push.py`(그 파일 하나만 올리기), `Evening-Summary.ps1`(예약 등록)입니다.

### 어디서 어떻게 읽는가

- `data/sources.json`에 적힌 공개 채널의 웹 미리보기(`t.me/s/<채널 이름>`)를 평일 17:41(KST)에 한 번 읽습니다. 로그인하지 않습니다.
- 채널당 한 쪽(최근 20글)이고, 직전 판까지 닿지 못하면 한 쪽만 더 읽습니다. 요청 사이 3초, 전체 30요청·6분이 상한입니다(월요일·연휴 뒤에는 40요청·8분). 2026-10-08 실측은 24채널 26요청 122초였습니다.
- 고르는 순서는 수집 → 묶기 → 점수 → 조립 → 검사입니다. 여러 곳이 함께 다뤘는지를 세어 '꼭 볼 것'을 3건까지 싣고, 나머지는 30줄까지 싣습니다. 기준을 넘은 묶음이 없으면 0건으로 냅니다.
- 같은 날 다시 돌리면 첫 실행과 같은 창에서 다시 계산합니다(알림 줄 하나만 다릅니다). 수집이 부족했던 날 못 읽은 글은 다음 판이 다시 읽습니다.

### 켜고 끄기, 내리기

- 예약 수집·게시·감시는 저장소 변수 `EVENING_ENABLED`가 `true`일 때만 돕니다. 변수가 없거나 다른 값이면 채널을 읽지도, 판을 올리지도 않습니다. 시범 동안에는 결과를 보기 전에 적어 둔 '오늘 꼭 3건'과 견줘 기준을 고칩니다.
- 내리는 방법은 두 가지입니다.
  1. `data/digest_overrides.json`에 항목 id나 채널 이름을 적습니다. 화면이 바로 감추고, 다음 판부터 조립에서 빠집니다. 판 전체는 `withdraw`로 내립니다.
  2. `evening` 워크플로를 main에서 수동 실행하며 '내리기'를 켭니다. 오늘 판을 빈 판으로 바꾸고 지난 판 파일과 목차를 지웁니다. 다음 예약 실행이 다시 올리지 않게 하려면 `EVENING_ENABLED`도 끕니다.
- 이미 커밋된 판 파일은 화면에서 내려도 git 기록에 남습니다. 남는 것은 위 '싣는 것'뿐입니다. 게시할 때 실행 기록에 붙는 사본은 하루 뒤 지워집니다.

### 삭제·정정 요청

### 한계

- 텔레그램 약관(콘텐츠 라이선싱 조항)은 이용자의 통상적인 이용이 아닌 목적으로 콘텐츠에 접근하는 것을 제한하고, 공개 채널이라는 예외를 두지 않습니다. 이 화면의 수집은 그 조항과 긴장이 있습니다. 그래서 글의 문장을 싣지 않고, 하루 한 번 미리보기 한 쪽만 읽으며, 요청이 오면 내립니다. 약관이 실제로 어떻게 해석되는지는 확인하지 못했습니다. AI 요약은 여기에 더해 플랫폼 자료를 AI에 쓰는 것을 제한하는 조항과도 긴장 관계에 있습니다(위 'AI 요약').

## 매일 갱신할 때의 주의사항과 복구

- 기존 예약은 KST 화~토 07:17입니다(미국 영업일 다음 날). GitHub 실행 지연은 5시간까지 허용합니다. 주말·월요일을 단순히 “24시간 미갱신”으로 경고하지 않습니다. 가격은 실시간 시세가 아니며 지표별 관측일이 다릅니다.
- 한국 자료 수신은 일시적인 연결 오류·HTTP 408/429/5xx 일부에만 한 번 재시도합니다. 요청 10초, 자료 묶음 45초(국고채 발행계획·매입/교환은 각 60초, 통화안정증권 결과 50초·발행 계획 40초 — 맨 뒤라 앞 묶음이 다 쓴 날엔 남은 시간만), 전체 네트워크 예산 180초를 적용하며 Actions 단계에도 4분 제한이 있습니다(180초 + 마지막 요청 10초 + 쓰기). 시간 초과·구문 오류가 나면 마지막 성공 자료와 날짜를 보존합니다.
- 이전보다 과거 날짜로 돌아온 시세, 7일을 초과해 오래된 일별 관측, 빈·중복 입찰 일정, 이번 달과 다른 일정을 정상 갱신으로 승인하지 않습니다. 같은 날짜의 정정치는 허용합니다. 긴 연휴에도 7일 기준은 작동하므로 오류인지 휴장인지 원 출처로 확인합니다.
- `korea-status.json`은 수집 **시작 전**과 **종료 후**에 별도로 기록합니다. 수집 프로그램이 시간 초과로 종료돼 `korea.json`을 못 쓰더라도 이전 정상 표시를 그대로 믿지 않습니다. 성공 판정은 이번 실행 시각의 자료와 12개 묶음 성공 여부를 확인한 뒤에만 기록합니다. 이번 실행의 새 자료인데 일부 묶음만 실패했으면(모두 실패면 `failure`) `partial`(`ok: false`, 실패 묶음 목록 `failed`)로 기록하고, 화면은 그 묶음에만 경고를 붙입니다 — 전에는 묶음 하나의 실패가 정상으로 갱신된 다른 카드까지 '최근 한국 자료 갱신에 실패했습니다'로 덮었다(2026-10-14). Actions 알림은 그대로 실패로 반영합니다.
- 브라우저는 실행 실패·미완료·예약 갱신 누락을 한국 시장과 홈 요약에 표시합니다. 화면을 오래 열어 둬도 1분마다 자료 나이를 다시 계산합니다. **새 값 자체는 페이지를 새로 열거나 새로고침할 때 읽습니다.** 파일 하나의 응답이 멈춰도 15초 뒤 나머지 화면은 표시합니다.
- JSON은 같은 디렉터리의 임시 파일을 완성한 뒤 교체합니다. 기존 JSON을 읽을 수 없거나 저장에 실패하면 원 파일을 덮지 않고 실행을 실패 처리합니다.

경고가 계속되면 **출처·갱신**에서 실패한 자료·마지막 성공일을 확인하고, [Actions 실행 로그](https://github.com/yun-macrolab/macro-regime-check/actions/workflows/daily.yml)의 해당 단계를 확인합니다. 일시 장애가 해소되면 `daily`의 **Run workflow → main**으로 재실행할 수 있습니다. 출처의 표·단위·PDF 형식이 바뀐 경우에는 파서를 고쳐야 합니다. 숫자나 성공 플래그를 손으로 바꿔 정상처럼 만들지 않습니다. GitHub 자체가 실행·배포를 하지 못한 경우는 새 파일을 게시할 수 없으므로 기존 화면에서 예정 시각 경과를 감지합니다.

### 비밀값·저장소 변수 넣는 법 (2026-11-09)

값은 저장소 어디에도 쓰지 않습니다. GitHub의 **Settings → Secrets and variables → Actions**에서 운영자가 넣고, GitHub Secret은 넣은 뒤 다시 읽을 수 없어 고칠 때는 값 전체를 새로 붙여 넣습니다(Update secret).

| 이름 | 종류 | 꼴 | 쓰는 단계 | 없으면 |
|---|---|---|---|---|
| `BLIND_PATTERNS` | Secret | 공개 전 검사어 여러 줄 — 한 줄에 하나, 빈 줄과 `#`로 시작하는 줄은 무시, 폭 없는 공백·제어 문자 금지 | 공개 전 검사(매 실행 처음·봇 커밋 직전) | '검사 불가' — 봇 커밋과 페이지 배포가 멈춥니다 |
| `SEC_USER_AGENT` | Secret | `<이름 또는 프로젝트 이름> <연락 이메일>` 한 줄(200자 이하, 줄바꿈 없음) | 'SEC 공시 조달 참고 자료 받기' 하나 | SEC 요청을 하나도 하지 않고 조달 칸 셋이 '연락처 미설정'(2026-11-09 운영자가 설정 — 같은 날 첫 실제 수신) |

- **임계값은 추정치입니다.** 대부분은 개인 조사 보고서의 추정 수치이고, 기간 프리미엄·SOFR의 0.25%p와 지준 재확대 조건(3개월 +0.3%p, 근원 PCE 2%)은 보고서에 수치가 없어 구현 때 정한 제안값입니다. 어느 쪽도 적중률로 검증한 기준이 아닙니다. 2026-10-14에 더한 두 규칙의 0.5%p는 문헌값(실업률, Sahm 2019)과 과거 자료를 한 번 훑어 정한 값(근원 물가)이고, 이것도 앞으로를 검증한 기준은 아닙니다. 규칙은 첫 실행 직전까지 다듬었고(판정 경계·3값 논리·계단 제외), 바뀐 내용은 커밋 기록에 남아 있습니다.
