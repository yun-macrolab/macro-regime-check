# macro-regime-check

미국 공개 통계(FRED) 22개 시리즈를 받아 코드로 공개된 **규칙 11개**가 충족됐는지 판정하고, 미국 영업일 다음 날 아침(KST 화~토 07:17)마다 자동으로 갱신하는 점검 페이지입니다.

**[점검 페이지 보기](https://yun-macrolab.github.io/macro-regime-check/)** · 투자 판단이나 권유가 아니라, 공개된 규칙을 공개 통계에 적용한 출력입니다.

| 구분 | 내용 |
|---|---|
| 하는 것 | FRED 원자료 수신(API 키 없이 공개 CSV) → 전년비·3개월 변화·60영업일 상관 등 계산 → 규칙별 충족 / 미충족 / 판정 불가 → 공개본·그래프 자료·상태 기록 → 페이지 배포 |
| 싣지 않는 것 | 제 시장 견해(듀레이션·커브 판정과 점수), 재배포가 제한된 지수(S&P·ICE·Moody's 계열 4개)의 값 — 규칙 충족 여부와 자료 상태만 보여 주고, S&P500은 원값을 되살릴 수 없는 60영업일 상관과 연속 일수만 계산값으로 싣습니다 |
| 하지 않는 것 | 매매 신호·수익률 전망, 규칙의 적중률 평가(아직 검증 전) |
| 참고로 싣는 것 | 한국 국고채 금리(3·5·10·30년) — **공개 통계가 아니라** 증권사 리서치팀 텔레그램 공개 채널 글에서 옮긴 숫자이고, 규칙 판정에는 쓰지 않습니다([아래](#참고-한국-국고채-금리)) |

22개 중 원/달러·M2 유통속도·IG 스프레드 3개는 규칙에 쓰지 않고 자료 상태만 보여 줍니다.

## 규칙 11개

| 신호 | 충족 조건 |
|---|---|
| 기업대출 증가율 대 명목 성장률 | C&I 대출 전년비가 명목GDP 전년비보다 낮으면 |
| 은행의 비은행 금융기관 대출 | 전년비(재분류로 보이는 주간 +40십억달러 이상 증가 계단 제외)가 10% 미만이면 |
| 신용 스프레드 | Baa−10년 스프레드가 12개월 저점보다 0.4%p 이상 넓어지거나 HY OAS가 4.61%p를 넘으면 |
| 주가-금리 60영업일 상관 | S&P500 일간 수익률과 미 10년 금리 일간 변화의 60영업일 상관이 126영업일 이상 계속 양(+)이면 |
| 10년−2년 금리차 | 0보다 작으면 |
| 실질금리와 기대인플레이션 | 10년 실질금리가 2% 미만이고 10년 BEI가 3개월 전보다 높으면 |
| 근원 물가 | 근원 PCE 전년비가 3% 이하이면 (근원 CPI는 참고) |
| 10년 기간 프리미엄 | Kim-Wright 10년 기간 프리미엄이 3개월 전보다 0.25%p 이상 낮아지면 |
| 단기 조달금리 SOFR | 3개월 전보다 0.25%p 이상 높아지면 |
| 지준과 통화승수 | 지준/명목GDP가 9% 미만이거나, 3개월 새 0.3%p 이상 늘고 근원 PCE 전년비가 2%를 넘으면 |
| 미 증권·투자업 고용 | 고용 전년비가 0보다 작으면 |

판정 로직과 임계값은 [`scripts/regime_rules.py`](scripts/regime_rules.py)의 표(`TH`)에서, 페이지에 싣는 규칙 문장은 [`scripts/render_public.py`](scripts/render_public.py)의 `public_rules()`에서 나옵니다(문장 속 임계값도 `TH`에서 읽습니다). 판정 코드 원문에는 원본 파이프라인의 시나리오 구분 문구가 남아 있지만, 페이지와 공개본에는 싣지 않습니다. 계산 규칙 몇 가지:

- **월간·분기 전년비는 1년 전 같은 달이 있을 때만** 계산합니다. 결측월을 전 달 값으로 메우지 않습니다.
- **복합 조건은 3값 논리**로 판정합니다. 한쪽 자료가 없어도 결론이 나는 경우만 충족·미충족으로 쓰고, 나머지는 '판정 불가'로 둡니다.
- 임계값과 비교하기 전에 계산값을 소수 여섯째 자리까지 반올림합니다(0.40이 0.3999…로 계산돼 경계를 놓치지 않게).

## 동작 방식

GitHub Actions가 예약 시각마다 돕니다([`daily.yml`](.github/workflows/daily.yml)).

1. **검사** — 공개 전 검사와 단위 테스트
2. **갱신** — 수집·판정 → 공개본(`data/public.json`) → 그래프 자료(`data/charts.json`) → 국고채 참고 자료(`data/ktb.json`) → 한국 시장(`data/korea.json`) → 상태 기록(`data/status.json`) → 새 산출물 포함 공개 전 검사 → 봇 커밋
3. **배포** — `site/`와 `data/`만 GitHub Pages로
4. **알림** — 갱신, 그래프 자료 생성, 국고채 참고 자료·한국 시장 자료 수신 중 하나라도 실패하면 실행을 실패로 끝냅니다

실패한 날에는 직전 공개본이 그대로 남고, 페이지 첫 화면에 실패 배너와 마지막 성공 시각이 나옵니다. 그래프 자료만 실패한 날에는 직전 그래프가 남고 "그래프는 그 날짜 기준"이라고 표시합니다. 예정된 실행이 아예 빠진 경우에도 배너를 띄웁니다. 수신에 실패한 시리즈가 3개 이상이면(캐시로 대신한 것 포함) 그날은 기록하지 않습니다 — 오래된 캐시를 오늘 결과로 내보내지 않기 위해서입니다.

## 그래프

페이지의 **금리의 구조**(최근 5년, 주간)와 **규칙 카드마다 작은 추이**(최근 3년)를 그립니다.

| 그래프 | 그리는 것 |
|---|---|
| 미 10년 금리 분해 | 명목 10년 · 10년 실질 · 10년 BEI |
| 기간 프리미엄과 10년−2년 | Kim-Wright 10년 기간 프리미엄 · 10년−2년 |
| 국고채 금리 · 국고채 장단기 금리차 | 참고 절의 국고 3·10·30년 금리와 10년−3년·30년−10년 금리차(글이 올라온 날 기준, 2026-09-03부터) |
| 규칙 카드 10개 | 그 규칙이 실제로 비교하는 양과 임계값 점선 (예: NDFI 전년비와 10%, 기간 프리미엄 3개월 변화와 −0.25%p, SOFR 3개월 변화와 +0.25%p) |

- **카드 값과 같은 계산입니다.** [`scripts/render_charts.py`](scripts/render_charts.py)가 표본 날짜마다 원자료를 그 날까지 자르고 규칙 점검과 같은 함수로 계산하므로, 그래프의 마지막 점이 카드에 적힌 값과 같습니다(테스트가 강제).
- 신용 스프레드 카드는 재배포 제한 자료라 그래프가 없습니다.
- 그래프마다 밑에 출처 줄이 붙습니다 — FRED 그래프는 FRED 시리즈 페이지가 적은 출처와 FRED 경유를, 국고채 그래프는 채널 이름과 금리 기준을 적고, 계산한 선이면 이 저장소가 계산했다는 표시를 붙입니다.
- 그래프는 외부 라이브러리 없이 [`site/charts.js`](site/charts.js)로 그립니다. 마우스·손가락·키보드(←/→)로 날짜별 값을 보고, "표로 보기"로 모든 값을 표로 볼 수 있습니다.

## 화면

금융 단말기의 문법을 빌린 한 장짜리 화면입니다(2026-10-08 개편).

- **국면 모니터** — 규칙 11개를 표 하나에 모읍니다: 주제 · 규칙 · 최근 값 · 자료일 · 작은 추이선 · 판정. 값과 추이선은 같은 양입니다(추이선이 3개월 변화면 값도 3개월 변화이고, 그 이름을 규칙 아래에 적습니다). 원자료를 공개할 수 없는 규칙은 값 자리에 '비공개'로 나옵니다. 좁은 화면에서는 주제 열을 숨기고 자료일을 값 아래에 적습니다. 규칙 이름을 누르면 그 주제 화면으로 갑니다.
- **명령줄과 번호 키** — 맨 위 명령줄에 화면 이름(일부만 쳐도 됩니다)이나 번호를 치고 Enter. 없는 이름이면 칠 수 있는 이름을 알려 줍니다. 입력 칸 밖에서는 숫자 키 1~9로 화면을 바꾸고 `/`로 명령줄에 갑니다. 숫자 키 단축은 머리의 **단축키 버튼**으로 끌 수 있습니다.
- **시세 띠** — 미국 10년 금리와 규칙별 첫 수치가 한 줄로 흐릅니다. 마우스를 올리거나 초점을 두면 멈춥니다. 국고채 참고 자료의 숫자는 싣지 않습니다(그 숫자는 고지가 함께 보이는 절에서만 나갑니다).
- **화면 8·9** — 8은 저녁판(시범), 9는 읽기 노트입니다. 둘 다 아래에 따로 적었습니다.
- **수신 상태** — 기준일·마지막 성공 시각·실행 결과 줄은 띠 아래에 보입니다(아침 갱신과 따로 도는 저녁판·읽기 노트 화면에서는 감춥니다). 머리의 수신 표시는 화면을 열어 둔 동안에도 다시 판정해, 다음 갱신 시각이 지나면 '갱신 지연'으로 바뀝니다.
- **움직임 버튼** — 시세 띠, 값이 들어오는 깜박임, 그래프 선이 그려지는 움직임을 켜고 끕니다. 끄면 시계도 분 단위로만 바뀝니다. 기기가 '움직임 줄이기'로 설정돼 있으면 꺼진 채로 시작하고, 고른 값은 그 브라우저에 기억됩니다.
- **글꼴만 바깥에서 받습니다.** IBM Plex Sans KR · IBM Plex Mono를 Google Fonts에서 불러오므로 페이지를 열면 그 서버로 요청이 나갑니다. 스크립트는 저장소의 것만 씁니다.

## 참고: 한국 국고채 금리

페이지의 **한국 국고채** 절(꼬리표 '채널 자료 · 규칙 판정 제외')은 위 규칙 점검과 성격이 다릅니다(2026-10-08 추가).

- **공개 통계가 아닙니다.** KB증권 리서치본부 채권크레딧팀이 텔레그램 공개 채널([t.me/jk_bond](https://t.me/jk_bond))에 평일 아침 올리는 '채권시장 일일동향' 글에서 국고채 3·5·10·30년 금리와 전일 대비 숫자만 옮깁니다(금리 기준은 그 글에 적힌 민평3사 — 민간 채권평가사 세 곳 평균). 글의 해설, 미국·크레딧·환율 구역, 글에 있던 글자는 옮기지 않습니다. 이 저장소는 KB증권·채권평가사와 관계가 없고, 채널 운영자나 금리 산출처가 요청하면 이 절을 내립니다.
- **규칙 판정에 쓰지 않습니다.** [`scripts/ktb_fetch.py`](scripts/ktb_fetch.py)는 판정 코드와 떨어져 있고, 판정·공개본·그래프 스크립트는 `data/ktb.json`을 읽지 않습니다(공개 전 검사만 모든 파일을 훑습니다).
- 날짜는 글이 올라온 날(한국 시간)이고, 글이 아침에 올라오므로 값은 직전 영업일 금리입니다. 장단기 금리차(10년−3년, 30년−10년)는 이 저장소가 그 금리로 계산합니다. 이 형식의 글은 2026-09-03부터 있어 그 전 자료는 없습니다.
- 예약 실행 한 번에 검색 결과 한 쪽만 요청합니다(처음 채울 때만 여러 쪽). 자동 갱신이 글보다 먼저 돌면 하루 늦게 반영됩니다.
- **형식이 바뀌면 닫힌 쪽으로 실패합니다.** 구역 머리글이 다르거나, 네 만기나 스프레드 줄 중 못 읽은 것이 있거나, 금리가 범위를 벗어나거나, 금리와 글에 적힌 스프레드가 맞지 않으면 그 글은 버립니다. 가장 최근 글을 읽지 못한 날은 실행을 실패로 끝내고, 페이지는 직전에 읽은 값과 그 날짜를 보여 줍니다. 글의 제목 줄이 바뀌어 알아보지 못하는 경우는 '새 글 없음'과 구분되지 않으므로, 마지막으로 읽은 글이 12일 넘게 묵으면 실패로 끝냅니다. 저장 파일이 깨져 있으면 덮어쓰지 않고 실패로 끝냅니다. 페이지에 나가는 문구는 코드에 정해 둔 것뿐입니다(테스트가 강제).

## 한국 시장 학습 화면

`한국 시장` 아래에 **금리·커브 / 신용·단기자금 / 수급·입찰**을 제공합니다. 기존 11개 규칙과 별개인 참고 자료입니다.

- **금리·커브**: 한국 3·10년, 미국 10년, 한국 10년−3년, 한국−미국 10년 금리차.
- **신용·단기자금**: 회사채 AA− 3년−국고채 3년, CD·CP 91일, CP−CD 금리차.
- **수급·입찰**: 외국인 3·10년 국채선물 당일·최근 5·20관측일 누적 순매수(계약수, 스프레드 거래 포함), 월별 국고채 입찰 일정과 최근 일반 국고채 경쟁입찰 결과(입찰금액·응찰률·가중평균 낙찰금리).

## 읽기 노트

읽은 글을 **제 말로** 옮긴 공부 기록입니다(사이트의 9번 화면 `#notes`, 글마다 `#notes/<파일 이름>`). 꼴은 한 줄 결론 · 요약 · 개념 풀이 · 내 틀과의 연결 · 질문 3개 · 그림 · 원문 링크입니다.

- **번역이나 전재가 아닙니다.** 원문의 문장·그림·표는 싣지 않고 인용도 하지 않습니다. 원문은 링크로만 잇습니다. 틀린 곳은 Issues로 알려 주세요.
- **새 노트 쓰기** — `notes/YYYY-MM-DD-영문-소문자.md`를 쓰고 `python -X utf8 scripts/notes_build.py`를 돌려 `data/notes.json`을 함께 커밋합니다(`--check`는 쓰지 않고 비교만 합니다). 둘이 어긋난 채 올리면 테스트가 막습니다. 그 테스트는 아침 워크플로의 앞 단계라, 배포뿐 아니라 다음 날의 FRED 갱신도 함께 멈춥니다.
- **받는 문법** — 머리말(제목 · 날짜 · 출처 · 원문 제목 · 원문 주소 · 저자 · 발행일 · 읽는 시간 · 난이도 · 한 줄 결론), `##`·`###` 제목, 문단, 목록, 표, `**굵게**`, `[글](https://…)`, `::질문` 아래 번호 목록 3개. 그 밖의 것(원시 HTML, 인용문, 코드, 그림 `![]`, 맨 주소, https가 아닌 링크, 보이지 않는 글자)은 파일 이름과 줄 번호를 찍고 멈춥니다.
- **그림 세 종류** — ① `::사이트그래프 <규칙 키> | 캡션`: 사이트가 평일 아침마다 받는 규칙 그래프를 그대로 싣습니다. ② 펜스 `도식` 안의 JSON: 직접 그리는 개념도입니다(수치 축 없음, 화면 읽기용 설명 `alt` 필수). ③ `::정적그래프 <그래프 키> | 캡션`: `scripts/notes_charts.py`로 받아 둔 공개 통계(`data/notes_charts.json`)를 연 단위로 그립니다.
- **정적 그래프의 자료 조건** — FRED 계열 쪽의 저작권 표시가 "Public Domain: Citation Requested"나 "Copyrighted: Citation Required"이고 마지막 값이 2025년 이후일 때만 싣습니다. "Pre-approval Required"이거나 표시를 읽지 못하면 스크립트가 파일을 쓰지 않습니다. 그래프 아래에 출처(FRED 경유)·계산한 선 표시·받은 날을 적습니다. 이 스크립트는 손으로 돌리며 아침 워크플로에서는 돌지 않습니다.
- **테스트** — 아침 테스트에 함께 돕니다: `test_notes_build.py` 50개 · `test_notes_charts.py` 21개 · `test_notes_site.py` 22개, 그리고 가짜 DOM 위에서 실제 노트를 그려 보는 `node --test scripts/test_notes_render.cjs` 20개.

## 저녁판(시범)

평일 저녁, 텔레그램 공개 채널 여러 곳이 함께 다룬 주제를 규칙으로 골라 보여 주는 화면입니다(`#evening`). 아침 점검표의 규칙 판정과 무관한 참고 자료이고, 금리의 방향이나 강도, 매매 판단을 내지 않습니다. 2026-10-08에 시범으로 열었고, 낱말 사전과 점수 기준은 시범 동안 바뀝니다.

### 싣는 것과 싣지 않는 것

- 싣는 것: 미리 정한 낱말 사전의 낱말과 그 낱말을 쓴 채널 수, 출처 라벨, 정해 둔 문구, 숫자와 단위, 글을 올린 시각, `https://t.me/<채널 이름>/<글 번호>` 꼴의 원문 링크입니다.
- 읽을거리를 늘리려고 2026-10-08 저녁부터 아래 것도 싣습니다. 어느 것도 채널 글의 글자가 아닙니다.
  - 글마다: 글 길이 구간(200자 미만 '짧은 글' · 700자 이상 '긴 글' · 그 사이 '보통 길이'), 그 글에서 걸린 사전 낱말의 수, 그림·파일이 붙었다는 표시입니다. 그림·파일 자체와 글자 수는 싣지 않습니다.
  - 묶음마다: 두 곳 이상이 직접 쓴 낱말과 그 채널 수(전달 글은 세지 않습니다), 묶인 글의 수, 첫 글과 마지막 글의 시각입니다. 대표 낱말이 A·B급이고 직전 판에도 있었으면 그때의 채널 수를 함께 적습니다. 낱말이 같다는 뜻일 뿐 같은 묶음이라는 뜻은 아닙니다.
  - 낱말 풀이: 이 사이트가 직접 쓴 한 줄(60자 안쪽)이고, 그 판에 나온 낱말의 것만 싣습니다. 낱말의 뜻만 적으며 그 글의 내용·시세·전망·평가는 담지 않습니다. 나라를 밝히지 않은 지표(CPI·GDP 등)는 미국 지표로 세므로 풀이가 그 글이 다룬 나라와 다를 수 있습니다.
  - 풀이 옆의 바깥 링크: 규칙에 적어 둔 주소 50개(도메인 19개)뿐입니다. t.me가 아닌 링크는 이것과 삭제 요청 양식뿐입니다. '공식 자료'는 정부·중앙은행·국제기구의 쪽입니다(통계 쪽이 아니라 기관의 첫 쪽일 때도 있습니다). '시계열'과 '문서 모음'은 세인트루이스 연은이 통계와 문서를 모아 싣는 쪽(FRED · FRASER)이고, 그 가운데 변동성 · 신용 스프레드 · 미 소비심리 · 모기지는 민간 기관이 내는 지표입니다. 채널 글이 가리킨 주소는 싣지 않습니다.
- 낱말을 늘어놓을 때는 글에 나온 순서가 아니라 채널 수 · 등급 · 가나다 순으로만 놓습니다. 낱말 목록이 글의 요약처럼 읽히지 않게 하려는 것입니다.
- 숫자는 두 곳 이상이 같은 낱말 곁에 똑같이 쓴 것만 싣습니다. 예외는 '속보형·개인 채널이 혼자 쓴 글' 절 하나이고, 그 절의 숫자는 한 곳만 쓴 숫자라고 화면에 적습니다. 이 절에는 숫자 없이 낱말만 있는 줄도 실립니다(첫 두 줄에 사전 낱말이 있는 글, 채널당 5줄까지).
- 싣지 않는 것: 채널 글의 문장·첫 줄, 사진·표 그 자체, 링크 카드의 기사 제목입니다. AI 요약 문장은 채널 글의 문장이 아니라 AI가 자기 말로 쓴 것이며, 원문과 길게 겹치면 싣지 않습니다. 규칙판(고르기·묶기·점수)은 LLM을 쓰지 않습니다. 'AI 요약' 표시가 붙은 문장만 운영자 PC에서 AI가 따로 씁니다(아래 'AI 요약').
- 채널 글의 글자는 공개되는 것(`data/*.json`, 화면, Actions 로그) 어디에도 나가지 않습니다. 원문은 실행기의 작업 폴더(`.work/evening/`)에만 있고 커밋·아티팩트·로그에 넣지 않습니다. 공개 JSON의 모든 문자열이 허용 목록(사전 낱말 · 정해 둔 문구 · 규칙에 적힌 풀이와 주소 · 숫자와 단위 · 시각 · 길이 구간 이름)으로 다시 조립되는지를 게시 전에 두 번 검사합니다. 화면도 낱말과 풀이를 사전의 지문과 견줘 한 번 더 거릅니다.
- 판이 크기 상한(36KB)에 걸리면 낱말 풀이 → 단독 줄 → 나머지 표 순으로 덜어 내고, 덜어 낸 판에는 알림 줄을 붙입니다.
- 낱말과 숫자만으로는 글의 뜻을 잘못 짚을 수 있습니다. 무슨 내용인지는 링크를 눌러 원문에서 읽어야 합니다.

### AI 요약 (시범)

꼭 볼 것과 일부 항목에는 'AI 요약' 표시가 붙은 한두 문장이 실립니다. 이 문장은 채널의 글이 아니라 AI(Claude)가 쓴 것입니다.

- **무엇을 읽고 무엇을 쓰는가** — 게시된 규칙판에서 꼭 볼 것 전부와, 채권·애널 그룹 원천 채널 두 곳 이상이 직접 쓴 항목을 합쳐 6개까지 고릅니다. 항목마다 그 채널들의 전달 아닌 글을 3건까지(글마다 1,500자까지) 읽고, 무슨 일인지를 한국어 한두 문장(140자 이하)으로 씁니다. 개인·속보형 채널의 글과 전달 글은 읽히지 않습니다. 읽을거리가 300자에 못 미치는 항목은 쓰지 않습니다.
- **어디서 도는가** — GitHub Actions가 아니라 운영자의 PC에서 돕니다. 고르는 일(규칙판)은 지금처럼 LLM 없이 Actions가 하고, PC는 고른 글의 본문을 텔레그램 웹 미리보기에서 한 번 더 받아(채널마다 한 번, 3초 간격, 20요청까지) 도구를 모두 끈 Claude Code에 건넵니다(`--safe-mode --tools ""`, 새로 만든 빈 폴더, 꼭 필요한 환경 변수만). 글을 건네기 전에 매번 원문 없는 점검 호출로 도구·MCP·스킬이 비어 있는지, 물음 말고 다른 것이 모델에 실리지 않았는지(입력 토큰 수)를 확인하고, 하나라도 어긋나면 글을 건네지 않습니다. 채널 글의 본문은 PC의 메모리에만 있고 파일·로그·저장소에 남기지 않습니다. 다만 그 본문이 요약을 위해 Anthropic의 모델로 전송된다는 점은 분명히 적어 둡니다.
- **검사** — 문장마다 여섯 가지를 봅니다: 꼴(평서문 한두 문장, 주소·@·채널 이름 없음), 정해 둔 권유·전망·평가·광고 표현, 베낌(원문과 20자 이상 이어 겹치거나, 글자 3-gram의 60% 이상이 한 글에 있거나, 조사만 바꿨거나, 여러 글의 긴 토막을 이어 붙인 문장), 숫자(원문에 같은 단위로 있는가, '예상·전월·전년'이 붙은 숫자를 그 말과 함께 썼는가), 낱말(그 항목과 읽힌 글의 낱말인가, 방향·결정을 글과 다르게 쓰지 않았는가), 이름(사람 이름·영문 약어가 읽힌 글에 있는가). 하나라도 걸린 문장은 버리고 사유별 개수만 남깁니다. 걸린 문장이 있어도 규칙판은 그대로 나갑니다.
- **틀릴 수 있습니다** — 검사는 정해 둔 꼴만 잡습니다. 숫자도 사전 낱말도 없이 뜻을 틀리게 옮긴 문장, 다른 말로 쓴 전망은 걸러 내지 못합니다. 짧은 어구는 원문과 겹칠 수 있습니다. 사람이 확인한 뒤 싣는 것이 아니라 검사를 통과하면 바로 실립니다. 문장은 길잡이일 뿐이니 원문 링크에서 확인해 주세요.
- **약관과의 긴장** — 텔레그램 약관에는 플랫폼에서 얻은 자료를 AI·기계학습에 쓰는 것을 제한하는 조항이 있고, 공개 채널이라는 예외를 두지 않습니다. 이 기능은 그 조항과 긴장 관계에 있습니다. 그래서 읽는 범위를 채권·애널 원천 채널의 글 몇 건으로 좁히고, 본문을 저장하지 않고, 원문을 옮겨 적지 않는 검사를 두었으며, 채널 운영자가 요청하면 그 채널을 목록에서 내립니다(아래 '삭제·정정 요청').
- **PC가 꺼진 날** — PC가 꺼져 있거나, Claude 로그인이 만료됐거나, 점검에서 멈췄거나, 문장이 모두 검사에 걸린 날에는 문장 없이 규칙판만 나갑니다. 예약 작업은 평일 17:45·23:30과 이튿날 07:30에 돌고(늦게 다시 계산된 판을 따라가기 위해서입니다), 달라진 것이 없으면 채널도 모델도 다시 부르지 않습니다.
- **내리는 방법** — 저장소 변수 `EVENING_ENABLED`를 끄면 PC도 규칙판 실행을 시작하지 않고 채널을 읽지도 모델을 부르지도 않으며, 올라가 있는 문장은 다음 실행에서 빈 것으로 바뀝니다. 완전히 내릴 때는 변수를 끄고, 내리기 실행(`evening.yml`의 takedown)을 돌리고, PC의 예약 작업을 지웁니다(`Evening-Summary.ps1 -Unschedule`).
- **파일** — `data/digest_picks.json` 하나(가장 최근 한 판의 문장만). 코드는 `scripts/evening/evening_llm.py`(고르기·받기·묻기), `digest_picks.py`(형태와 문장 검사), `picks_push.py`(그 파일 하나만 올리기), `Evening-Summary.ps1`(예약 등록)입니다.

### 어디서 어떻게 읽는가

- `data/sources.json`에 적힌 공개 채널의 웹 미리보기(`t.me/s/<채널 이름>`)를 평일 17:41(KST)에 한 번 읽습니다. 로그인하지 않습니다.
- 채널당 한 쪽(최근 20글)이고, 직전 판까지 닿지 못하면 한 쪽만 더 읽습니다. 요청 사이 3초, 전체 30요청·6분이 상한입니다(월요일·연휴 뒤에는 40요청·8분). 2026-10-08 실측은 24채널 26요청 122초였습니다.
- 고르는 순서는 수집 → 묶기 → 점수 → 조립 → 검사입니다. 여러 곳이 함께 다뤘는지를 세어 '꼭 볼 것'을 3건까지 싣고, 나머지는 30줄까지 싣습니다. 기준을 넘은 묶음이 없으면 0건으로 냅니다.
- 같은 날 다시 돌리면 첫 실행과 같은 창에서 다시 계산합니다(알림 줄 하나만 다릅니다). 수집이 부족했던 날 못 읽은 글은 다음 판이 다시 읽습니다.

### 켜고 끄기, 내리기

- 예약 수집·게시·감시는 저장소 변수 `EVENING_ENABLED`가 `true`일 때만 돕니다. 변수가 없거나 다른 값이면 채널을 읽지도, 판을 올리지도 않습니다. 시범 동안에는 결과를 보기 전에 적어 둔 '오늘 꼭 3건'과 견줘 기준을 고칩니다.
- 내리는 방법은 두 가지입니다.
  1. `data/digest_overrides.json`에 항목 id나 채널 이름을 적습니다. 화면이 바로 감추고, 다음 판부터 조립에서 빠집니다. 판 전체는 `withdraw`로 내립니다.
  2. `evening` 워크플로를 main에서 수동 실행하며 '내리기'를 켭니다. 오늘 판을 빈 판으로 바꾸고 지난 판 파일과 목차를 지웁니다. 다음 예약 실행이 다시 올리지 않게 하려면 `EVENING_ENABLED`도 끕니다.
- 이미 커밋된 판 파일은 화면에서 내려도 git 기록에 남습니다. 남는 것은 위 '싣는 것'뿐입니다. 게시할 때 실행 기록에 붙는 사본은 하루 뒤 지워집니다.

### 삭제·정정 요청

채널 운영자, 글쓴이, 읽는 사람 누구나 저장소 Issues의 '삭제·정정 요청 (저녁판)' 양식으로 요청할 수 있습니다. 채널 이름과 판 날짜만 적으면 됩니다. 채널 운영자가 요청하면 그 채널을 목록에서 내립니다. 운영자는 한 사람이고 응답 시각을 약속하지 못합니다.

### 한계

- 텔레그램 약관(콘텐츠 라이선싱 조항)은 이용자의 통상적인 이용이 아닌 목적으로 콘텐츠에 접근하는 것을 제한하고, 공개 채널이라는 예외를 두지 않습니다. 이 화면의 수집은 그 조항과 긴장이 있습니다. 그래서 글의 문장을 싣지 않고, 하루 한 번 미리보기 한 쪽만 읽으며, 요청이 오면 내립니다. 약관이 실제로 어떻게 해석되는지는 확인하지 못했습니다. AI 요약은 여기에 더해 플랫폼 자료를 AI에 쓰는 것을 제한하는 조항과도 긴장 관계에 있습니다(위 'AI 요약').
- 규칙은 낱말 사전과 숫자의 일치만 봅니다. 같은 일을 다룬 글이 따로 떨어지거나, 드물게 다른 일이 한 묶음이 될 수 있습니다. 낱말 사전과 점수 기준은 시범 동안 바뀝니다.
- 예약 시각에는 당일 국고채 종가가 아직 없어 금리의 방향 표시가 비고 '전일 종가'로 나옵니다.
- 일정표(`data/calendar.json`)에는 공식 일정 쪽에서 직접 읽은 날짜만 넣습니다. 미 CPI·미 고용 일정은 아직 없습니다.

### 운영 메모

- `data/calendar.json`은 `scripts/evening/test_calendar.py`의 출처 장부와 같은 커밋에서 고칩니다. 파일만 고치면 검사가 떨어져 그날 수집이 돌지 않습니다. `data/sources.json`에서 채널을 빼거나 끄는 것은 그대로 해도 됩니다.
- 저녁 코드는 평일 17:30~18:00에 main으로 올리지 않습니다(아침 워크플로와 같은 실행 그룹이라 기다리던 실행이 취소될 수 있습니다). 올린 뒤에는 Actions에서 두 실행이 취소 없이 끝났는지 봅니다.
- 실행이 실패로 끝나면 GitHub 알림 메일이 옵니다: 수집 부족, 꼭 볼 것 0건 3판 연속, 미리보기 형식 바뀜, 채널 확인 필요(제목 해시가 다름 · 글 번호가 거꾸로 감 · 채권 채널이 3판 이어서 안 읽힘), 단계 실패. 무엇을 하면 풀리는지는 알림 문구에 있습니다.

## 매일 갱신할 때의 주의사항과 복구

- 기존 예약은 KST 화~토 07:17입니다(미국 영업일 다음 날). GitHub 실행 지연은 5시간까지 허용합니다. 주말·월요일을 단순히 “24시간 미갱신”으로 경고하지 않습니다. 가격은 실시간 시세가 아니며 지표별 관측일이 다릅니다.
- 한국 자료 수신은 일시적인 연결 오류·HTTP 408/429/5xx 일부에만 한 번 재시도합니다. 요청 10초, 자료 묶음 45초, 전체 네트워크 예산 150초를 적용하며 Actions 단계에도 4분 제한이 있습니다. 시간 초과·구문 오류가 나면 마지막 성공 자료와 날짜를 보존합니다.
- 이전보다 과거 날짜로 돌아온 시세, 7일을 초과해 오래된 일별 관측, 빈·중복 입찰 일정, 이번 달과 다른 일정을 정상 갱신으로 승인하지 않습니다. 같은 날짜의 정정치는 허용합니다. 긴 연휴에도 7일 기준은 작동하므로 오류인지 휴장인지 원 출처로 확인합니다.
- `korea-status.json`은 수집 **시작 전**과 **종료 후**에 별도로 기록합니다. 수집 프로그램이 시간 초과로 종료돼 `korea.json`을 못 쓰더라도 이전 정상 표시를 그대로 믿지 않습니다. 성공 판정은 이번 실행 시각의 자료와 8개 묶음 성공 여부를 확인한 뒤에만 기록합니다.
- 브라우저는 실행 실패·미완료·예약 갱신 누락을 한국 시장과 홈 요약에 표시합니다. 화면을 오래 열어 둬도 1분마다 자료 나이를 다시 계산합니다. **새 값 자체는 페이지를 새로 열거나 새로고침할 때 읽습니다.** 파일 하나의 응답이 멈춰도 15초 뒤 나머지 화면은 표시합니다.
- JSON은 같은 디렉터리의 임시 파일을 완성한 뒤 교체합니다. 기존 JSON을 읽을 수 없거나 저장에 실패하면 원 파일을 덮지 않고 실행을 실패 처리합니다.

경고가 계속되면 **출처·갱신**에서 실패한 자료·마지막 성공일을 확인하고, [Actions 실행 로그](https://github.com/yun-macrolab/macro-regime-check/actions/workflows/daily.yml)의 해당 단계를 확인합니다. 일시 장애가 해소되면 `daily`의 **Run workflow → main**으로 재실행할 수 있습니다. 출처의 표·단위·PDF 형식이 바뀐 경우에는 파서를 고쳐야 합니다. 숫자나 성공 플래그를 손으로 바꿔 정상처럼 만들지 않습니다. GitHub 자체가 실행·배포를 하지 못한 경우는 새 파일을 게시할 수 없으므로 기존 화면에서 예정 시각 경과를 감지합니다.

## 공개 범위와 안전장치

- **원자료와 공개본을 나눴습니다.** 원자료 캐시와 원본 계산 결과는 커밋·배포하지 않는 작업 폴더에만 두고, 공개본은 허용 목록에 있는 값만 옮겨 만듭니다. 공개 문구를 정해 두지 않은 새 규칙이 원본에 생기면 공개본 만들기가 실패합니다.
- **공개 전 검사**([`scripts/check_blind.py`](scripts/check_blind.py)) — 개인정보·로컬 경로·토큰 같은 검사어가 작업 트리와 **과거 커밋 전체**(지운 파일, 커밋 작성자 정보 포함)에 하나라도 있으면 멈춥니다. 검사어 목록 자체는 공개하지 않고(로컬 파일·GitHub Secret), 인코딩을 바꾼 우회(전각 문자, HTML·JSON 이스케이프, CP949·UTF-16)도 찾습니다. 읽을 수 없는 파일은 통과시키지 않습니다.
  - push 전 로컬 훅(`.githooks/pre-push`, `git config core.hooksPath .githooks`로 켬)에서 걸리면 push가 멈춥니다.
  - GitHub Actions에서는 매 실행 처음과 봇 커밋 직전에 돌고, 걸리면 봇 커밋과 페이지 배포를 멈춥니다(이 검사는 push된 뒤에 돕니다).
- **그래프 자료도 같은 허용 목록으로** 만듭니다. 재배포가 제한된 지수의 원값은 어느 날짜 것도 싣지 않고(S&P500은 원값을 되살릴 수 없는 60영업일 상관만), 문구는 코드에 정해 둔 것만 나갑니다.
- **출처 표기** — 공개본(`data/public.json`)에는 시리즈마다 FRED 권장 인용(원 출처, 영문 제목 [ID], retrieved from FRED; 시리즈 주소, 기준일)을, 페이지에는 시리즈별 FRED 링크·마지막 관측일·오래된 자료 표시와 그래프별 출처 줄을 싣습니다.
- **SOFR 고지** — 뉴욕 연은 이용약관(2023-06-09 개정)은 SOFR 같은 참조금리 자료를 쓰거나 배포할 때 정해진 고지·면책 문구를 요구합니다(2026-09-30 원문 확인). 그 문구와 DTCC 문장(원문 그대로), 뉴욕 연은 기본 출처 표기(© 연도)는 꼬리말과 SOFR 카드(그래프 아래)에, "SOFR 3개월 변화는 이 저장소가 계산한 값"이라는 표시(한·영)와 관계없음 고지는 SOFR 카드에 싣습니다. JSON에도 같은 문구가 들어갑니다(`public.json`·`charts.json`의 `attribution`, SOFR 규칙·그래프의 `notices`). 이 사이트는 뉴욕 연은·세인트루이스 연은(FRED)과 관계가 없습니다(영문 고지는 꼬리말). 2026-09-30 이전 커밋의 기록 파일에는 이 고지가 없었고, 지금 저장소의 기록 파일은 값은 그대로 두고 고지·인용만 채워 다시 저장했습니다.
- **계산값 표시** — 전년비·3개월 변화·비율·상관처럼 이 저장소가 계산한 값은 카드에 '계산값'으로, 그래프는 출처 줄에 '이 저장소가 계산한 값'으로 표시합니다.

구현한 동작을 확인하는 검사이며, 규칙이 시장을 잘 맞히는지를 잰 것은 아닙니다.

## 한계

- **임계값은 추정치입니다.** 대부분은 개인 조사 보고서의 추정 수치이고, 기간 프리미엄·SOFR의 0.25%p와 지준 재확대 조건(3개월 +0.3%p, 근원 PCE 2%)은 보고서에 수치가 없어 구현 때 정한 제안값입니다. 어느 쪽도 적중률로 검증한 기준이 아닙니다. 규칙은 첫 실행 직전까지 다듬었고(판정 경계·3값 논리·계단 제외), 바뀐 내용은 커밋 기록에 남아 있습니다.
- **발표 시차** — GDP 같은 분기·월간 지표는 수 주에서 수 개월 늦게 반영됩니다. 페이지의 자료 기준일을 함께 봐야 합니다.
- **개정치** — FRED 값은 나중에 고쳐집니다. 과거 날짜를 다시 계산한 결과는 작업 폴더(비공개)에만 남기고, 공개본(`data/public.json`)과 `data/history/`는 되돌리지 않습니다.
- **결측** — 근원 CPI는 2025-10이 비어 있어, 그 달이 기준이 되는 12개월 뒤 전년비는 '산출 불가'로 둡니다.
- GitHub Actions 예약 실행은 늦게 돕니다. 지금까지 일곱 번은 모두 예약 시각보다 3~4시간 뒤(한국 시간 오전 10~11시대)에 끝났고, 페이지의 '예정된 갱신이 반영되지 않았다' 배너는 5시간까지 기다립니다.
- **국고채 참고 절은 남의 채널 글에 기대고 있습니다.** 글 형식이 바뀌거나 채널 미리보기가 닫히면 그날부터 갱신이 멈춥니다(실패 알림과 페이지의 날짜 표시로 드러납니다).

AI가 쓴 코드는 제가 규칙과 검증 기준을 정하고 결과를 검수하는 방식으로 썼습니다. 코드 커밋마다(봇의 자동 갱신 커밋 제외) AI 공동 작성 표시가 남아 있습니다.

## 직접 돌려 보기

```sh
python -X utf8 scripts/regime_check.py                      # FRED 수신·판정 → .work/ (원자료·원본 결과, 커밋하지 않음)
python -X utf8 scripts/render_public.py --out .work/public  # .work/ → 공개본 (기본값 data/는 저장소 파일을 덮어씀)
python -X utf8 scripts/render_charts.py --out .work/public  # .work/ → 그래프 자료 charts.json
python -X utf8 scripts/ktb_fetch.py --out .work/public      # 채널 글 → 국고채 참고 자료 ktb.json (t.me에 요청 1회)
```

API 키가 필요 없습니다. `regime_check.py`에 `--offline`을 붙이면 받아 둔 캐시만 씁니다(국고채 수신에는 오프라인 모드가 없습니다). 공개 전 검사(`scripts/check_blind.py`)는 검사어 목록이 있어야 돌아가며, 목록은 공개하지 않습니다.
